# Athena Agent

A unified intelligent collaboration portal for the 3 employees of the CALEO department: each person has their own Pi assistant; the team shares conversations, knowledge graph, Wiki, and Kanban. Everything underneath is powered by open-source components (Pi + LightRAG + LLM Wiki + CodeGraph), with cross-machine multi-agent collaboration via a git repo.

## Language

**Employee**:
Real human members of the CALEO department (A/B/C), accessing the portal via browser, each with an independent git identity.
_Avoid_: user, member

**Pi (Agent)**:
The underlying AI coding agent (`@earendil-works/pi-coding-agent`), each employee's intelligent assistant. Embedded in the portal backend via AgentSession.
_Avoid_: bot, assistant

**AgentSession**:
Pi's core class, an in-process embedded agent session instance. One per employee (long-lived, naturally isolated).
_Avoid_: session, worker process

**Personal Conversation**:
An employee's private chat with their own Pi (independent AgentSession).
_Avoid_: DM, private chat

**Team Conversation**:
The collaboration space for all employees + shared Pi. POC is assistant mode; ultimate goal is Pi can speak (Plan B).
_Avoid_: group chat

**Goal (G)**:
A top-level objective launched by a Pi. Globally incrementing numbering (G1, G2...). Each Goal has its own folder containing the grill output **Goal.md**.
_Avoid_: project, initiative

**Spec (S)**:
A feature container under a Goal (G1.S1). Generated by PM reading G1/CONTEXT.md via to-spec. Contains spec.md and all tickets beneath it.
_Avoid_: feature, module

**Ticket (T)**:
An atomic task under a Spec (G1.S1.T1). Decomposed by Eng Director using to-tickets. Claimed by Workers via the claim lock.
_Avoid_: task, issue

**Claim Lock**:
The mechanism for a Worker to claim a ticket: modify frontmatter status=in_progress + git push atomic operation. Push conflict = mutual exclusion lock.
_Avoid_: lock, reservation

**Wiki**:
LLM incrementally generated interlinked markdown knowledge base (Karpathy pattern).
_Avoid_: knowledge base

**Knowledge Graph**:
Entity relationship visualization (LightRAG NetworkX graph data).
_Avoid_: graph view

**Kanban**:
Pi-driven task board (git-driven, docs/kanban/ is the source of truth).
_Avoid_: board, taskboard

## Rules

- **Employees/Pis have independent git identities** — git commits distinguish who performed the operation
- **Markdown is the sole source of truth** — docs/kanban/*.md stores all task state, no local SQLite
- **Grill output = G1/Goal.md** — it IS the input to to-spec; project root CONTEXT.md is only a glossary
- **ADR is only written when all three conditions are met** — hard to reverse + surprising + real tradeoff
- **Claim lock only claims backlog** — rejected tickets must first notify Eng Director to regenerate
- **First 3 stages (GRILL/SPEC/PLAN) completed by a single agent** — same Pi plays Consultant → PM → Eng Director
