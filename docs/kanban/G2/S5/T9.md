# G2.S5.T9: Fix docling Picture Descriptions (OpenRouter key issue)

## Problem

T6 enabled picture descriptions in `parse_doc.py`, but PDF images still appear as
`<!-- image -->` placeholders with no description. Root cause:

The athena server process env has `OPENROUTER_API_KEY` as an **unexecuted base64 command string**:
```
OPENROUTER_API_KEY=$(echo c2stb3It... | base64 -d)
```
When `parse_doc.py` reads `os.environ["OPENROUTER_API_KEY"]`, it gets this literal
`$(echo ... | base64 -d)` string (NOT the decrypted key). OpenRouter auth fails →
`do_picture_description` silently degrades → images stay as placeholders.

## Implementation

1. Ensure athena server is started with a **decrypted (plaintext)** `OPENROUTER_API_KEY`
   in its process env (the base64 `$(echo ... | base64 -d)` form must be resolved by the
   starting shell, not passed literally).
   - Fix the launch command / wrapper so `$(echo ... | base64 -d)` is evaluated at shell
     level before the node process starts.
2. OR make `parse_doc.py` self-sufficient: detect the `$(echo ... | base64 -d)` form and
   decrypt it before using the key.
3. Verify: re-parse a PDF with images → Markdown has descriptions (e.g. "Figure: ...").
