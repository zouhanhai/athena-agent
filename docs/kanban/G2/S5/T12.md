# G2.S5.T12: Delete Document from Wiki Tree (both pipelines)

## Problem

There is no way to delete a single document from the knowledge base. The only
option today is clearing the whole database. Deleting one doc should remove it from
BOTH llm_wiki and LightRAG so a re-upload with the same name works (avoids the
LightRAG 409 "already contains" error).

## UX

In the Wiki tree, when a **file** node is selected, show a **Delete** button (next to
Refresh). Clicking asks for confirmation, then deletes the doc from both systems and
refreshes the tree. This makes it obvious which file is being deleted (you see it in
the tree).

## 409 duplicate-name user message (IMPORTANT — same ticket)

Today when a re-upload hits the LightRAG 409 ("document already contains 'X'"), the user
only sees "LightRAG: failed" with NO reason:
- The 409 lives in `stage.error` (`ingesting_lightrag.error`), but the frontend only
  renders `task.error` (top-level). Top-level `task.error` is only set when BOTH systems
  fail ("Both knowledge systems failed"), so a 409 with llm_wiki-ok shows nothing useful.

Fix:
1. Backend `tasks.ts`: when a stage fails, promote that stage's error to the top-level
   `t.error` so the UI surfaces the real reason (not just "Both knowledge systems failed").
2. Frontend `KnowledgeView.vue`: also render per-stage error text, OR surface a friendly
   message when the error indicates a duplicate (contains "already contains" / "409" /
   "duplicate"): e.g. "This file already exists in the knowledge base. Delete it in the
   Wiki panel, then upload again."
3. Keep the raw error available too (tooltip / secondary line).

## Backend

1. Add `DELETE /api/kb/doc` (or `POST /api/kb/doc/delete`) body `{ path: "wiki/concepts/foo.md" }`.
2. Resolve the page's `documentId` / LightRAG `file_source` (the file stem, e.g. `foo` or `Sommerseminar-L-sen`).
3. **LightRAG**: call `POST /documents/delete_document` with `{ doc_ids: [<id>], delete_llm_cache: true }`.
   Need to find the LightRAG doc id — either by matching `file_path` from `/documents` list, or pass the file_source.
4. **llm_wiki**: delete the wiki file on disk (`~/athena-data/wiki/wiki/<path>.md`), then trigger
   `POST /projects/{id}/sources/rescan` so Source Watch removes it from the index; also rebuild `wiki/index.md`.
   (llm_wiki exposes no delete HTTP endpoint — `delete_file`/`vector_delete_page` are Tauri commands
   not exposed over HTTP, so delete the file directly + rescan.)

## Frontend

`web/src/views/WikiView.vue`:
- Track selected file node (already have `activePath`).
- Show a **Delete** button when a file is selected.
- `t-dialog` confirm ("Delete this document from both Wiki and Knowledge Graph?").
- On confirm → call delete API → refresh tree.

## Reference
- `server/src/kb/lightrag.ts` (add deleteDocument: POST /documents/delete_document)
- `server/src/kb/llmwiki.ts` (add deleteFile: fs delete + rescan + rebuild index)
- `server/src/routes/kb.ts` (add DELETE /api/kb/doc)
- `web/src/views/WikiView.vue` (tree + Delete button)
- LightRAG DeleteDocRequest: `{ doc_ids: string[], delete_file?, delete_llm_cache? }`
