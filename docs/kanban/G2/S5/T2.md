# G2.S5.T2: Backend Ingestion API + Task Queue

## Task

Build the backend ingestion endpoints with task status tracking.

## Implementation

### 1. Routes (server/src/routes/kb.ts)
- `POST /api/kb/ingest`: multipart file upload → call docling parse (S5.T1) → kb/ingest dual pipeline (S3.T2)
- `POST /api/kb/ingest-url`: JSON { url } → docling fetch → dual pipeline
- `GET /api/kb/task/:id`: return task status { id, source, status, progress }

### 2. Task Queue
- In-memory queue (POC): each task = { id, source, status, stages }
- **Stages tracked per system**:
  - `parsing` (docling) → `ingesting_lightrag` → `ingesting_llmwiki` → `done`
  - Or failed per system (e.g. LightRAG ok but llm_wiki failed)
- `progress`: number (0-100) + per-stage status
- Async processing (non-blocking upload response → poll task status)
- Both systems' ingest results reported independently

### 3. Tests
- node:test: upload flow (mock docling + ingest), URL flow, task status transitions
