# G2.S5.T13: Knowledge Graph Topic Filter

## Problem

The Knowledge Graph currently shows the FULL graph (all entities), which gets
cluttered as the knowledge base grows (e.g. 272 nodes). Users want to focus on one
topic (e.g. "sommerseminar") and see only that topic's nodes.

## How it works (feasibility confirmed)

- LightRAG graph nodes carry a `file_path` property (e.g. `Sommerseminar-L-sen.md`)
  → identifies the source wiki file.
- Wiki files have a `topic` in frontmatter (e.g. `sommerseminar`).
- So: node.file_path → wiki file → node.topic. Filter nodes by selected topic.

## Backend

1. `retrieval.ts` `normalizeGraph`: **preserve** each node's `file_path` (currently dropped).
2. Build a `file_path → topic` map from the llm_wiki pages (read wiki frontmatter `topic`).
3. Enhance `getGraph(label?, topic?)`: when `topic` is given, keep only nodes whose
   `file_path` maps to that topic (and their edges, plus adjacent nodes to keep the
   subgraph connected).
4. `routes/kb.ts` GET `/api/kb/graph?topic=sommerseminar`.
5. Optionally expose `GET /api/kb/graph/topics` → list of available topics for the filter.

## Frontend

`web/src/views/KnowledgeView.vue`:
- Add a **topic filter** (TDesign `t-select` or `t-radio-group`) near the graph controls:
  `All topics` (default) + one option per available topic.
- On change, re-fetch `/api/kb/graph?topic=...` (or filter client-side if data loaded).
- Show a note like "Showing X of Y entities" when filtered.

## Reference
- `server/src/kb/retrieval.ts` (normalizeGraph currently drops file_path)
- `server/src/routes/kb.ts` (GET /api/kb/graph)
- `web/src/views/KnowledgeView.vue` (graph panel)
- `web/src/kb/graph.ts` (mapKnowledgeGraph)
