# G2.S5.T14: Content Deduplication (exact hash + semantic similarity)

## Problem

Today uploading the same content twice (e.g. Sommerseminar as BOTH `.pdf` and `.docx`)
hits a LightRAG 409 "already contains" because docling derives the same stem. But two
files with DIFFERENT names but SAME content are also ingested twice (no dedup). We want
content-level dedup: identical content is stored once; near-duplicates are caught by
semantic similarity.

## Key change — name must NOT be used to reject duplicates

Stop relying on the file name / stem for dedup. Instead:
1. **docling keeps the original extension in the output filename** so same-name
   different-format files (pdf/docx) get DIFFERENT file_sources → no more 409.
   Change `derive_stem` in `parse_doc.py` from `Path(name).stem` to `Path(name).name`
   (retain extension, e.g. `sommerseminar-l-sen.pdf`).
2. **Dedup is purely content-based** (normalized hash for exact; LightRAG embedding for
   approximate) — the name is just an identifier, never a rejection reason.

This pairs with the delete feature (T12) and 409 friendly message (T12): a real duplicate
upload is caught by content hash, not by "same name".

## Key facts (verified)

- Raw-file sha256 differs for identical-content pdf vs docx (different formats).
- docling markdown ALSO differs: PDF → `## headings`, DOCX → `**bold**` headings. So a
  plain markdown hash also differs → must NORMALIZE before hashing.
- llm_wiki has NO semantic-similarity capability (keyword/vector retrieval only).
- LightRAG HAS embedding (qwen3-embedding-8b) + `/query` → semantic similarity must run
  there, not in llm_wiki.

## Two-layer dedup

### Layer 1 — exact (normalized hash), runs before the parallel pipelines
1. docling parses → markdown.
2. Normalize markdown → plain text: strip `**`, `##`, `#`, `<!-- ... -->`, image/media
   placeholders, collapse whitespace/newlines, lowercase.
3. sha256(normalized_text). Keep a store of seen hashes (per project).
4. If hash exists → SKIP ingest, surface "This document's content already exists" (with
   the existing doc name). Do NOT hit LightRAG (avoids the 409) nor llm_wiki.

### Layer 1b — long docs (hundreds of pages)
- Split normalized text into pages/chunks (e.g. per N lines or ~1000 tokens).
- Compute per-chunk hash. Compare chunk-by-chunk against stored per-chunk hashes.
- If a doc's chunk-hash sequence matches an existing doc → duplicate. Otherwise ingest
  (and store the new chunk-hash sequence for future comparisons).
- Keeps comparison O(pages) and cheap; no LLM needed.

### Layer 2 — semantic (approximate), inside LightRAG pipeline
- After ingest, compute the new doc's embedding and compare cosine similarity to
  existing docs (reuse `/query` or a dedicated embedding endpoint).
- If similarity > threshold (e.g. 0.9) with an existing doc → flag as "near-duplicate"
  (but still stored; surface a notice to the user).
- This runs in LightRAG (has embedding), NOT llm_wiki.

## Backend

- `server/src/kb/dedup.ts` (new): normalizeMarkdown(text) → plain text; hashChunks(text);
  compareChunkHashes(a, b).
- Store seen hashes: reuse existing data (llm_wiki page contents or a small JSON/DB
  store keyed by project).
- In `tasks.ts run()`: after docling parse, compute normalized hash → if dup, mark task
  done with a `dedup` notice (skip both LightRAG + llm_wiki). If not, proceed as today.
- Semantic similarity hook in LightRAG ingest (optional, Layer 2).

## Frontend

`KnowledgeView.vue`: when a task ends in `dedup`, show a friendly notice
("This content already exists — skipped. It's the same as '<existing doc>'."). Reuse the
existing per-task notice area.
