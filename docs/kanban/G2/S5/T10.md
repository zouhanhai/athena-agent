# G2.S5.T10: Wiki Topic-Based Grouping

## Problem

llm_wiki classifies docs by **type** (concept/entity/source/query/comparison/synthesis),
so e.g. 3 Sommerseminar PDFs all land in `wiki/concepts/` with no thematic grouping.
The user expects related docs (3 Sommerseminar files) to group together by **topic**.

## Current behavior
- 3 Sommerseminar PDFs + example.com → all `type: concept` → all in `wiki/concepts/`
- No sub-grouping by topic/subject

## Implementation options
1. **Topic-based classification**: extend classify to also derive a topic key (e.g.
   "sommerseminar-2026") and place docs under `wiki/<topic>/` or `wiki/<type>/<topic>/`.
2. **Naming/folder convention**: ingest docs under a topic folder derived from the doc
   subject, so related docs share a folder.
3. **Wikilinks**: build `[[topic]]` links to connect related pages (llm_wiki's graph index).

## Reference
- `docs/knowledge-rag-design.md` §2.2 (wiki auto-hierarchy, currently type-only)
- `server/src/kb/ingest.ts` (classify → category dirs)
- `server/src/kb/llmwiki.ts` (classify prompt)
