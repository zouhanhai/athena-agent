# G2.S3.T2: Dual-Pipeline Ingestion Service

## Task

Build the ingestion service that feeds parsed Markdown into both knowledge systems.

## Implementation

### 1. kb/ingest.ts
- `ingestMarkdown({title, content, source})`:
  - LightRAG: `kb/lightrag.ingestText(content)`
  - llm_wiki: write markdown file to llm_wiki project's wiki dir + rescan (`sources/rescan`)
  - Return per-system status (success/failure)

### 2. Backend Route
- `POST /api/kb/ingest` (Fastify): body `{ title, content, source }` → calls ingestMarkdown
- Dependency injection: register with kb services (like chat routes)

### 3. Verification
- Ingest a sample Markdown → confirm present in LightRAG (query returns it) + llm_wiki (files show it)
- Error handling: one system fails → report partial status

- Unit tests (10 new: ingest service 7 + route 3) with injected clients/fs; full suite 55 tests pass, typecheck clean.
- Live verification (`src/kb/verify-ingest.ts` + HTTP route smoke test): sample doc lands in **both** systems — LightRAG hybrid query returns the doc in references; llm_wiki file tree shows `wiki/<doc>.md` and keyword search returns it (score 39).

> Note: llm_wiki Source Watch scans the project's internal `raw/sources/`/`wiki/` dirs — the shared `~/athena-data/input` dir is not auto-mirrored. Ingestion therefore writes directly to `<project.path>/wiki/` (per ticket: "write markdown file to llm_wiki project's wiki dir + rescan").
