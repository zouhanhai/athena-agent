# G2.S3.T3: Pi OpenRouter + Tool Registration + Capability Routing

## Task

Switch Pi models to OpenRouter and register knowledge tools with capability-based routing.

## Implementation

### 1. Pi Model Configuration (OpenRouter)
- `~/.pi/agent/models.json` (+ models-store.json): update so Pi uses
  - Main: `deepseek/deepseek-v4-flash` via OpenRouter (base_url `https://openrouter.ai/api/v1`)
  - Vision: `qwen/qwen3.7-flash`
  - Embedding: `qwen/qwen3-embedding-8b`
- `~/.pi/agent/auth.json` already has openrouter provider (baseUrl + key)
- Verify: Pi AgentSession creates with OpenRouter models (no DeepSeek direct)

### 2. Knowledge Tool Registration (@earendil-works/pi-coding-agent)
- Register 5 tools in AgentSession:
  - `knowledge_search` (requireCapability anyOf: ['vector','keyword'])
  - `query_graph` (anyOf: ['vector','graph'])
  - `wiki_search` (allOf: ['wiki'])
  - `wiki_read_page` (allOf: ['wiki'])
  - `wiki_graph` (allOf: ['wiki','graph'])
- Each tool calls the backend kb/ service layer (T1)

### 3. Capability Routing
- llm_wiki → ["wiki","keyword","graph"], LightRAG → ["vector","graph"]
- Pi routes by intent + capability declaration + cost (ReAct)
- Multi-graph fusion: complex queries query multiple sources then fuse

### 4. Verification
- Pi AgentSession uses OpenRouter (log shows openrouter, not direct deepseek)
- Pi retrieves from LightRAG (semantic) + llm_wiki (wiki) via tools
- Intent routing correct (process→wiki, facts→RAG, relations→graph)
