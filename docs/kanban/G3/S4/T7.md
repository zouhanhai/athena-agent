# G3.S4.T7: Workbench polish

## 1. Commit panel: collapse the whole column
- `CodeTab.vue` `<aside class="commits-panel">` has `:class="{ 'is-collapsed': commitsCollapsed }"` but there is
  **NO `.commits-panel.is-collapsed` CSS rule** — so collapsing only shortens the list (`visibleCommits` slice),
  the 300px aside column still occupies layout. Add a rule so collapsed = the whole column disappears and
  the code view takes the space (e.g. `.commits-panel.is-collapsed { display: none; }` or a width collapse).
  Keep the HEAD commit visible when expanded; when collapsed the whole column is gone.

## 2. Kanban Goal/Spec tree layout harmony
- `KanbanTab.vue` `.kanban-goal` uses `align-items: baseline` — long goal titles wrap (G2/G3) while the spec
  badges flow separately, causing dead whitespace and misalignment. Redesign so each goal row is a clean
  two-part layout: fixed/narrow left (ref + title) and a right spec-badge area that wraps; columns align;
  long spec badge titles truncate with `text-overflow: ellipsis` (max-width + nowrap) instead of stretching
  the row. Remove the redundant "G1.S1 · G1.S1:" duplicate id in badges (show id once).

## 3. Kanban root index file (fast refresh)
- Pain: `GET /api/kanban` recursively scans `docs/kanban/G*/S*/T*.md` and opens every ticket file to read
  status on each refresh — slow.
- Design: maintain a **root index** (`docs/kanban/kanban-index.json`) that caches the ENTIRE board with
  enough info to render without re-scanning. Workbench reads this single file (fast).
- **Git strategy (decided 2026-08-09, avoids commit noise):**
  - The **index IS committed to git**, but it changes only when a ticket status changes — which is ALWAYS
    accompanied by the ticket file commit that is already the claim/complete mechanism. So the worker updates
    the index (`npm run kanban:index`) and includes it in the SAME commit as the ticket status change →
    **no extra commits**.
  - The **Progress Log lives inside `ticket.md`** — it is the LOCAL communication channel between the plan
    agent and the worker. It is written locally (minute-level) and read by the plan agent, but is **NOT
    committed** during work (keeps git history clean). It is pushed **only together with the ticket when the
    ticket is completed** (the final Progress Log goes up with the ticket's done commit). So high-frequency
    progress never pollutes history; only the final record ships.
- **Remote repos**: also read the remote repo's committed `docs/kanban/kanban-index.json` via a single
  GitHub `getFileContent` call (fast) instead of `scanRemoteBoard` full re-scan; fall back to the full scan
  when the remote has no valid committed index. This is the fix for the reported "local fast / remote slow"
  difference.

### `kanban-index.json` schema (enough info to render the whole board)

```jsonc
{
  "version": 1,
  "generated_at": "2026-08-09T16:00:00Z",   // UTC — when the index was last built
  "goals": [
    {
      "ref": "G3",                           // directory name
      "id": "g3", "title": "Multi-Agent Federation & Team Workbench",
      "owner": "eng-director", "status": "in_progress",   // Goal-level status
      "created_at": "...", "milestone": "M3",
      "specs": [
        {
          "ref": "G3.S4", "id": "s4", "title": "Workbench (GitHub-Style Content Area)",
          "owner": "eng-director", "status": "done",
          "milestone": "M3",
          "tickets": [
            {
              "ref": "G3.S4.T5", "id": "t5", "title": "Workbench shared repo selector + code scroll + kanban bound to repo + commits",
              "owner": "eng-director", "status": "done",
              "assignee": "opencode", "session_id": "ses_...",
              "blocked_by": [], "acceptance_criteria": ["..."],
              "created_at": "...", "started_at": "...", "completed_at": "...",
              "progress_last_row": "Implemented shared repo selector",   // from Progress Log, if present
              "progress_updated_at": "2026-08-09T15:50:00Z"
            }
          ]
        }
      ]
    }
  ]
}
```

Key points:
- Carries **full text intro** (id, title, owner, status, milestone) for every Goal/Spec/Ticket, so the
  Workbench Goal/Spec tree AND the ticket board render straight from this file.
- `progress_last_row` + `progress_updated_at` come from the ticket's Progress Log (M4 worker-progress),
  giving live status without opening the file.
- `generated_at` lets the frontend show "Refreshed HH:MM:SS" and detect staleness.
- Backend `GET /api/kanban` becomes: read `kanban-index.json` (fast); a `?rescan=1` forces a rescan to
  rebuild the index (fallback + refresh).
