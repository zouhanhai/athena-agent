# G3.S4.T5: Single shared repo selector in Workbench

## Task

Currently CodeTab and IssuesTab each own their own repo selector + `fetchRepos`. User wants ONE
repo selector at the **Workbench** level (sibling of the tabs): pick once, and both Code and Issues
use the same repo. KanbanTab reads the docs-scan board and has no repo select (unaffected).

## Implementation

1. `web/src/views/WorkbenchView.vue`:
   - Hold the shared repo state: `repos`, `repoValue`, `loading`, `error`.
   - Fetch repos once via `fetchRepos(sessionToken)` (`@/api/github`).
   - Render a single `<t-select>` repo selector in the Workbench header (above / sibling of the tabs).
   - Pass the selected repo down to CodeTab + IssuesTab as props (`repoValue` + `repos`), OR lift the
     shared repo into a small composable / the auth store. Prefer props (simple, explicit) unless a
     composable is cleaner.
2. `web/src/components/CodeTab.vue`: remove its own repo selector + `fetchRepos`; accept the shared
   repo (prop) and load branches/tree for it.
3. `web/src/components/IssuesTab.vue`: same — remove its repo selector + `fetchRepos`; load issues for
   the shared repo prop.
4. `web/src/components/KanbanTab.vue`: no change.
5. Tests: update Workbench/Code/Issues specs for the lifted selector; keep all green (web
   `npx vitest run`, `npx vue-tsc --noEmit`).
