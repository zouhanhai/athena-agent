# G3.S4.T5: Workbench — shared repo, code scroll, kanban bound to repo + refresh

## Task

Three Workbench improvements (confirmed 2026-08-09):

1. **Shared repo selector**: move the repo selector to the Workbench header (sibling of Code/Issues/
   Kanban tabs). One selection drives all tabs. Remove the per-tab repo selectors from CodeTab/IssuesTab.
2. **Code scroll fix**: the code file view (`CodeTab` `.code-lines`) doesn't scroll for long files —
   lines past ~50 are unreachable. Fix the height chain so the code pane scrolls.
3. **Kanban bound to the selected repo + refresh**: `KanbanTab` currently reads the LOCAL athena
   repo's `docs/kanban` via `GET /api/kanban` (no repo). Make it show the SELECTED repo's kanban
   (scan that repo's `docs/kanban` via GitHub `getFileContent`), with live ticket status
   (status / assignee / session_id) and a refresh button that re-fetches.

## Implementation

### 1. Shared repo selector (`web/src/views/WorkbenchView.vue`)
- Hold `repos`, `repoValue`, `loading`, `error`; fetch once via `fetchRepos(sessionToken)`.
- Render one `<t-select>` in the Workbench header. Pass the shared repo to CodeTab/IssuesTab/KanbanTab
  as a prop (or a small composable).

### 2. Code scroll fix (`web/src/components/CodeTab.vue` + `WorkbenchView.vue`)
- Ensure the height chain: WorkbenchView `.workbench-tabs` content area and the `t-tabs` panel must give
  CodeTab a bounded height so `.code-lines` (`flex:1; overflow:auto`) actually scrolls. Likely need
  `height` on the tab-panel / t-tabs content (e.g. `:deep(.t-tabs__content)` or the `tab-panel` wrapper).

### 3. Kanban bound to repo (`server/src/routes/kanban.ts` + `web/src/api/kanban.ts` + `KanbanTab.vue`)
- Backend: support `GET /api/kanban?repo=owner/repo` — fetch that repo's `docs/kanban/` tree + read
  Goal/Spec/Ticket `*.md` via the employee's GitHub credential (`getFileContent`), and read each
  ticket's live status (status / assignee / session_id from the ticket frontmatter). Reuse the existing
  board-scan parsing (`server/src/kanban/scan.ts`) on the fetched markdown.
- Frontend: `fetchBoard(sessionToken, repo?)`; `KanbanTab` takes the shared repo prop, shows ticket
  status (status / assignee / session_id) on each card, and a "Refresh" button re-fetches.
- Keep the local-athena behavior when no repo is selected (fallback) OR make Kanban require a repo —
  decide in impl.

### 4. Show recent commits in Code + manual refresh
- Backend: add `listCommits(credential, owner, repo, opts?)` to `server/src/github/client.ts`
  (`GET /repos/{owner}/{repo}/commits?sha=<branch>&per_page=30`) + a route
  `GET /api/github/repos/:owner/:repo/commits?ref=…` (scoped to the employee's credential).
- Frontend: `CodeTab` shows a commit panel/list (message, author, date, short sha) for the selected
  repo+branch. **Refresh is MANUAL only** (a refresh button) — no periodic polling, to avoid continuous
  GitHub API cost/rate-limit. Re-fetch on repo/branch change too.
- Show the current branch's HEAD commit (sha/message) prominently (e.g. in the code-view header).

### Tests
- Update Workbench/Code/Issues/Kanban specs for the lifted selector, scroll, and repo-bound board.
  Keep all green (web `npx vitest run`, `npx vue-tsc --noEmit`; server tests).

## Log

### 2026-08-09 — opencode (ses_g3s4_t5) — done

All four Workbench improvements implemented (web 324 tests, `vue-tsc` clean; server 568 tests, `tsc` clean).

1. **Shared repo selector**: lifted to the Workbench header (`WorkbenchView.vue`), fetched once via `fetchRepos`, drives Code/Issues/Kanban through a single `repo` prop. Per-tab selectors + `fetchRepos`/`repoValue` removed from `CodeTab`/`IssuesTab`.
2. **Code scroll fix**: TDesign panels render as `.t-tab-panel` (not `.t-tabs__panel`); the deep selector was targeting the wrong class so `.code-lines` never got a bounded height. Now `:deep(.t-tabs__content)` is a flex column and `:deep(.t-tab-panel)` fills it (`flex:1; min-height:0; overflow:hidden`), so long files scroll.
3. **Repo-bound kanban**: `GET /api/kanban?repo=owner/repo` scans the selected repo's `docs/kanban` via the employee's GitHub credential (`scanRemoteBoard` in `scan.ts` reuses `parseBoardFile`; live status/assignee/session_id come from ticket frontmatter). No-repo keeps the local-athena fallback. `KanbanTab` takes the repo prop, shows status/assignee/session on cards, and has a Refresh button.
4. **Commits (manual refresh only)**: `listCommits` on `GithubRestClient` (`/repos/{o}/{r}/commits?sha=…&per_page=30`) + `GET /api/github/repos/:owner/:repo/commits?ref=…`. `CodeTab` shows a commit panel (sha/message/author/date) with a Refresh button — no polling (avoid GitHub API cost); re-fetches on repo/branch change; HEAD commit shown in the code-view header.

Tests added/updated: `github-client`, `github-routes`, `kanban-scan`, `kanban-routes` (server); `code-tab`, `issues-tab`, `kanban-tab`, `github-api`, `kanban-api`, new `workbench-shared-repo` (web).
