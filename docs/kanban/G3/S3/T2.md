# G3.S3.T2: Single shared conversation context

## Task

One conversation (Pi AgentSession) across all pages; switching tab does not change context.

## Implementation

- Single global Conversation entity
- Context persists across tabs
- Deepseek cache rationale
- **Page-aware context injection (Vercel-inspired, §4.3)**: inject the current page's relevant agent capabilities into the context (Uploads→ingest, Workbench→GitHub, Wiki/Knowledge→knowledge) so agents respond with context-appropriate tooling

**One shared conversation entity across all pages**
- Client: the chat is a single global Pinia store (`web/src/stores/chat.ts`) mounted in `App.vue` — the same message list on every page (T1). Server: `AgentManager` keeps ONE persistent Pi AgentSession per user (unchanged).
- Test: `POST /api/chat` with the same userId across different `page` values reuses a single session (`manager.size === 1`); the store keeps `messages` intact across `setPage` calls.
- No page-level chat state anywhere — switching tabs changes only the center content.

**Page-aware context injection (Vercel-inspired, Spec 2b / g3-requirements §4.3)**
- New `server/src/agents/page-context.ts`: maps route path → page context (capabilities list). `/uploads`→ingest (docling/LightRAG/llm_wiki), `/workbench`→GitHub (repo tree/PR/issue/mutate), `/wiki` + `/knowledge`→knowledge tools (`knowledge_search`/`query_graph`/`wiki_*`). Prefix matching (e.g. `/workbench/issues` → Workbench).
- `registerChatRoutes` accepts an optional `page` body field and builds the prompt with `injectPageContext(page, message)` — the dynamic capability overlay is prepended per turn; the shared session/history is never altered. Unknown/empty page → message passes through unchanged.
- Client: `App.vue` watches the route and calls `chat.setPage(path)`; the store sends `page` with every message (`streamChat/sendChat` carry it); `GlobalChatPanel` shows a "Context: <page>" badge for mapped pages.
