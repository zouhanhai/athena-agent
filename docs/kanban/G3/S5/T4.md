# G3.S5.T4: Full per-stage ingest progress — LightRAG + llm_wiki every step shown

## Task

The Uploads page shows per-system processing stages, but the **LightRAG** stage only surfaces **chunk** progress
(`"Chunk N of M"`). The 4 sub-steps (`chunking` / `entity_extraction` / `graph_build` / `embedding`) are defined
in the UI but **never updated** by the backend — they stay pending. Also confirm llm_wiki's 3 sub-steps
(`classify` / `write_page` / `rebuild_index`) render live (they are wired via onStep).

Make every sub-step of both systems live and visible.

## Current behaviour

- `server/src/kb/lightrag-track.ts` `parseChunkProgress` only parses `"Chunk N of M"` → the backend maps only
  the `chunking` step to done (via `chunksCount` in `applyLightRagProgress`).
- LightRAG does **not** emit a separate embedding message — entity extraction + embedding upsert happen
  **inline per chunk** (`"Chunk N of M extracted X Ent + Y Rel"`). So there is no granular embedding API to read;
  the stage must be derived from chunk progress.
- llm_wiki already reports `classify` / `write_page` / `rebuild_index` via `onStep` (see `ingestLlmWiki`).

## Implementation

1. Backend `tasks.ts` `applyLightRagProgress` / track poller: map the real LightRAG state onto the 4 sub-steps:
   - once chunks are being processed (`chunksProcessed > 0` or pipeline shows `"Chunk N of M"`): `chunking` + `entity_extraction` running
   - when chunk total is known (`chunks_count`): `chunking` done
   - as chunk count approaches total / extraction lines seen: `entity_extraction` done
   - when the doc transitions to `processed`: `graph_build` + `embedding` done (final stage)
   Keep it best-effort and monotonic (never regress a done step).
2. Frontend `web/src/views/UploadsView.vue` / `web/src/kb/ingest.ts`: render all 4 LightRAG sub-steps + all 3 llm_wiki sub-steps with live status from the task endpoint; show chunk progress line.
3. Ensure task status endpoint (`GET /api/kb/task/:id`) returns the updated step statuses so the UI polls live.
4. Tests: backend step-transition logic (chunk progress → step statuses), frontend renders all steps.
