# G3.S8.T2: Ingest order fix — llm_wiki classify first → LightRAG gets topic

## Root cause (analyzed)

`server/src/kb/ingest.ts` `ingestMarkdown` currently does:

```
const lightragResult = await this.ingestLightRag(input.content, fileName); // FIRST, raw content (no frontmatter)
const llmwikiResult  = await this.ingestLlmWiki(fileName, input.content);  // THEN, classifies to topic
```

LightRAG ingests the **raw parsed content** (no frontmatter), so its documents have **no topic**. llm_wiki classifies *after* (or in parallel), so its topic never reaches LightRAG.

**Verified:** if content fed to LightRAG starts with frontmatter `topic: sommerseminar`, the LightRAG document's `content_summary` retains it, and nodes get a correct `file_path`. So the fix is to classify first and prepend frontmatter before ingesting into LightRAG.

**Also:** current chunking is the default **fixed_token** (1200 tokens). User prefers **paragraph_semantic** (`P`) — verified working via `/documents/text` with `chunking: {strategy: "paragraph_semantic"}` (doc metadata showed `process_options: "P"`, `chunk_method: "paragraph_semantic"`).

**Also:** `localClassify` misclassifies GroupReporting as `comparison` (the regex `\b(vs\.?|comparison|compare|differences?|alternatives?)\b` fires on financial-report text); Sommerseminar docs are company-internal events → should be `source`.

## Implementation

1. `server/src/kb/ingest.ts` `ingestMarkdown`:
   - Classify FIRST via `this.classify({ title, content })` → get `category` + `topic`
   - Build `frontmatterContent = withFrontmatter(category, title, content, topic)`
   - `ingestLightRag(frontmatterContent, fileName)` — LightRAG now sees the topic
   - Then `ingestLlmWiki(...)` as before
2. Chunking: pass `chunking: {strategy: "paragraph_semantic"}` in `ingestText` (lightrag.ts), or set `CHUNK_STRATEGY`/`process_options` env for new ingests.
3. Fix `localClassify` ordering/rules so GroupReporting → `source` (not comparison); confirm Sommerseminar docs classify to `source`.
4. Graph topic filtering: ensure `filterGraphByTopic` / frontend can map nodes to topic via `file_path` → LightRAG doc topic (from doc content_summary/metadata). Consider reading topic from LightRAG docs instead of llm_wiki mapping.
5. Re-ingest existing documents (GroupReporting, 3 Sommerseminar) so they carry topic + paragraph chunking.

## Taxonomy (authoritative)

Use **`docs/taxonomy.md`** as the classification authority:
- **type**: 13 kinds with criteria + counterexamples (report/minute/spec/manual/proposal/contract/policy/presentation/event/source/person/entity/concept) — replaces the research-oriented entity/concept/source/query/comparison/synthesis set.
- **topic**: hierarchical tree (sap/…, finance/…, it/…, client/<client>/<project>, corporate/…, internal/…) with detailed SAP subtree (consolidation/planning/business-warehouse/cloud/reporting/development/esg/migration + ai).
- The llm_wiki `classify` agent prompt must embed this taxonomy (type criteria + topic tree + existing topics) so it classifies consistently and reuses existing topics.
- `localClassify` / `localTopic` fallback must be updated to the same taxonomy.
