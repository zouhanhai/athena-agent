  - **`server/src/kanban/protocol.ts`** — claim/report/dispatch:
    - `claimTicket` — worker claims via git claim-lock: validates backlog + unassigned + never
      rejected, then writes status=in_progress / assignee / session_id / started_at and appends
      a Log entry. Rejected tickets throw (must go through Eng Director re-decompose).
    - `reportTicket` — worker reports `done` (implementation complete) or `in_review` (PR open,
      requires a positive `pr`), recording pr / branch / completed_at + a Log entry; done →
      in_review allowed after a PR opens.
    - `claimableTickets` / `dispatchNotice` / `dispatchNext` — planning-agent dispatch: select
      backlog + unassigned + unblocked (all blocked_by done/approved, per gdd/docs/design.md §10)
      tickets and build the "take <ref>" notification for a worker.
  - **`server/src/kanban/git-lock.ts`** — `GitClaimLock` wraps the protocol with add → commit →
    push; git push atomicity is the mutual-exclusion lock. A rejected push resyncs to the remote
    and backs off with `ClaimConflictError` when another worker won the race (reset --hard to the
    remote so the local board never diverges). `report` re-applies on conflict.
  - **`server/src/kanban/index.ts`** — public re-exports for protocol + git-lock.
  - Tests: `server/test/kanban-protocol.test.ts` (15), `kanban-git-lock.test.ts` (4, real two-worker
    git race: clone A claims + pushes, stale clone B loses push race → ClaimConflictError + reset).
  - Live-verified: report for this ticket was written + committed + pushed through GitClaimLock
    itself (dogfood); `dispatchNext` on the live board picks the next claimable ticket (G3.S6.T4).
  - Acceptance criteria met: claim lock works (git push = mutex), report works (done/in_review + PR
    number), dispatch works (planning agent notification).
