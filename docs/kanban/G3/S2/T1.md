# G3.S2.T1: Employee model + email login + RBAC

## Task

Employee table, email magic-link login, role-based RBAC.

## Implementation

- employees table: id/email/display_name/logo_url/role
- email magic-link login (Resend)
- role-based permission checks

## Reference
- `docs/kanban/G3/S2/Spec.md`
- `docs/g3-requirements.md`

## Log

- `server/src/employees/employees.ts` — `EmployeeRole` (`admin`/`member`), `EmployeeRecord`,
  `EmployeeRegistry` interface with `MemoryEmployeeRegistry` + `PostgresEmployeeRegistry`
  (lazy `CREATE TABLE IF NOT EXISTS employees` with `id/email/display_name/logo_url/role`,
  unique on email, `role` CHECK constraint). `seed()` creates the first admin from `ADMIN_EMAIL`.
- `server/src/employees/rbac.ts` — `Permission` union + `roleHasPermission` / `assertPermission`
  (`admin` = all; `member` = `agent.list` + `chat`). `PermissionDeniedError`.
- `server/src/employees/auth.ts` — `MagicLinkAuthService` (email magic-link login: `requestLogin`
  mails a one-time link, `verifyLogin` exchanges it for a session token + employee,
  `getEmployeeForSession` resolves sessions; never leaks whether an email is registered).
  `MemoryAuthTokenStore` + `PostgresAuthTokenStore` (`auth_login_tokens`/`auth_sessions`,
  SHA-256 token hashes). `ResendMailer` (REST API, `RESEND_API_KEY`) + `ConsoleMailer` (dev).
- `server/src/routes/employees.ts` — `POST /api/auth/login`, `POST /api/auth/verify`,
  `GET /api/me`, `GET/POST /api/employees`, `GET/PUT /api/employees/:email` with RBAC
  (401 unauthenticated / 403 role-denied).
- `server/src/app.ts` — wired `employees` + `auth` into `buildApp` (defaults: Postgres when
  `DATABASE_URL`, Resend when `RESEND_API_KEY`, else memory/console).

Tests (RED→GREEN): `server/test/rbac.test.ts` (4), `employees.test.ts` (9 + 2 PG integration),
`auth.test.ts` (8 + 1 PG integration), `employees-routes.test.ts` (17). Full magic-link flow
verified end-to-end against real Postgres (athena_test): login → link → verify → session → RBAC.
