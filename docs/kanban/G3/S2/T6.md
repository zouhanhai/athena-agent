# G3.S3.S2.T6: Settings as a standalone sidebar tab (page), not a dialog

## Task

G3.S2.T5 turned Settings into a **dialog** (`SettingsPanel.vue` opens a `t-dialog` from the sidebar footer)
containing Profile + Agents + Theme. The dialog experience is not great. Change Settings to a
**dedicated sidebar tab** that navigates to a full **page** (`/settings` → `SettingsView.vue`).

Content of the Settings page:
- **Profile** section (display name / animal logo / GitHub credential) — reuse the exact form/logic
  from `SettingsPanel.vue`.
- **Agents** section (`AgentManagement.vue`) — reuse as-is.
- **No Theme section** on the page — the sidebar `ThemeToggle` remains the single theme switch
  (the in-dialog Theme section is removed).

## Implementation

1. Create `web/src/views/SettingsView.vue` — a full page containing the Profile + Agents sections
   (lift the markup + logic out of `SettingsPanel.vue`'s `t-dialog` body; drop the dialog wrapper and the
   Theme section). Layout/typography consistent with other views (`.wiki-body`-style panel on a
   `--caleo-surface` card, CALEO theme vars).
2. Add a `/settings` route in `web/src/router/index.ts` → `SettingsView.vue`.
3. `web/src/components/SidebarNav.vue`: add a `Settings` nav item (path `/settings`, `SettingIcon`) to
   `navItems`; **remove** `<SettingsPanel />` from the footer (keep `<ThemeToggle />`).
4. Remove/stop using `SettingsPanel.vue` (or repurpose it — decide: simplest is to delete the dialog
   component and move its logic into SettingsView; keep AgentManagement.vue as a child).
5. Tests: sidebar shows a Settings nav item; /settings route renders Profile + Agents; no Theme section
   on the page; SettingsPanel dialog trigger gone from the footer. Keep all existing tests green
   (web `npx vitest run`, `npx vue-tsc --noEmit`).
