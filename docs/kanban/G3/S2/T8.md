# G3.S2.T8: Show current logo (selected) + GitHub credential mask in Profile

## Task

Two UX gaps in the Settings **Profile** section:

1. **Current logo not shown when it's "in use"**. `listLogos({excludeInUse: true})` excludes any logo used
   by another agent/employee. If the signed-in user's own logo is one of those (e.g. they picked shark,
   and shark is counted in-use), it is missing from the picker — so the user can't see/keep their current
   logo. The picker must ALWAYS show the user's current `logo_url`, highlighted (`is-selected`),
   regardless of the exclude-in-use filter.
2. **GitHub credential not shown when present**. `GET /api/me` doesn't return whether a token exists, so
   the GitHub field is always blank (`placeholder="ghp_…"`) even when the user already has a token stored.
   It should show a mask (e.g. `ghp_*****` / "a token is stored") so the user knows they have one, without
   ever exposing the secret.

## Implementation

1. Backend `GET /api/me` (server/src/routes/employees.ts): return
   `{ ...employee, github_has_credential: boolean, github_credential_type?: "token" }` by calling
   `registry.getGithubCredential(email)` (presence + type only — never the value).
2. Frontend `web/src/views/SettingsView.vue`:
   - logoOptions: always include the current `logoUrl` (even if absent from `logos.value`), and keep the
     existing `is-selected` highlight on it.
   - GitHub field: when `employee.github_has_credential`, show the input pre-filled with a mask
     (e.g. `ghp_*****` based on `github_credential_type`), disabled/readonly; clearing/retyping a real
     token replaces it (submit only sends a value when the user typed a new one).
3. `web/src/stores/auth.ts` + `web/src/api` types: carry `github_has_credential` / `github_credential_type`
   through the employee shape.
4. Tests: picker shows current in-use logo selected; github field masks when has_credential; /api/me returns
   github_has_credential. Keep all green (web `npx vitest run`, `npx vue-tsc --noEmit`; server tests).
