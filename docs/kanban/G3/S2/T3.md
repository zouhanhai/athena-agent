# G3.S2.T3: Agents archived under employees

## Task

Group agents under their owning employee; query agents by employee.

## Implementation

- link agents.owner_employee_id → employees
- GET /api/employees/:id/agents

## Reference
- `docs/kanban/G3/S2/Spec.md`
- `docs/g3-requirements.md`

## Log

- **Link `agents.owner_employee_id` → employees**: agents are archived/grouped under
  their owning employee. Referential integrity lives at the query layer: the new
  endpoint resolves the employee by id (404 when unknown) before listing their agents,
  so agents can never be returned under a non-existent employee. A hard SQL FK was
  deliberately avoided because the seeded `Athena` agent owns `owner_employee_id =
  "system"` (not an employee row, see `athena-seed.test.ts`).
- `server/src/routes/employees.ts` — added `GET /api/employees/:id/agents`
  (Bearer auth; RBAC `agent.list`, member-allowed) → resolves employee by id, then
  `agents.list({ ownerEmployeeId })` → `{ agents }`. `EmployeeRouteOptions` gains
  `agents: AgentRegistry`.
- `server/src/app.ts` — wired the agent `registry` into `registerEmployeeRoutes`.
- The `AgentRegistry.list({ ownerEmployeeId })` seam already existed from S1
  (memory + Postgres); this ticket surfaces it under the employee identity tree.

Tests (RED→GREEN): `server/test/employees-agents-routes.test.ts` (6 — owned agents,
isolation across employees, empty list, 404 unknown employee, 401 unauthenticated,
member RBAC allowed) + `server/test/agents-pg.test.ts` (1 Postgres integration —
`ownerEmployeeId` filter isolates per employee). `npm test` 280 pass / 0 fail;
`npm run typecheck` clean.

Acceptance criteria met: agents grouped under employee, query by employee works.
