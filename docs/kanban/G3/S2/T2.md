# G3.S2.T2: GitHub credential (encrypted) + scoped repos

## Task

Employee provides GitHub SSH/token at registration, stored encrypted; GitHub visibility scoped to user.

## Implementation

- github credential field, encrypted at rest
- register/update credential
- GET /api/github/repos scoped to user credential

## Reference
- `docs/kanban/G3/S2/Spec.md`
- `docs/g3-requirements.md`

## Log

- `server/src/employees/crypto.ts` — `SecretCipher` (AES-256-GCM) `encrypt`/`decrypt` with
  `v1:iv:tag:data` payloads; `createSecretCipher(keyHex)` validates a 32-byte key. Credential
  plaintext never touches storage.
- `server/src/employees/employees.ts` — `GITHUB_CREDENTIAL_TYPES` (`ssh`/`token`),
  `GithubCredential`/`GithubCredentialInfo` types. `EmployeeRegistry` gains
  `registerGithubCredential` (encrypt-at-rest upsert) + `getGithubCredential` (decrypt-on-read).
  Memory + Postgres backed; `employees` table gains `github_credential_type` +
  `github_credential_enc` columns (ALTER TABLE for existing DBs). `EmployeeCreateInput` accepts
  `github_credential` at registration.
- `server/src/github/client.ts` — `GithubRestClient.listRepos` calls `GET /user/repos` with the
  user's token (per-user visibility); `GithubAuthError` (401/403) + `GithubCredentialUnsupportedError`
  (SSH keys can't auth the REST API).
- `server/src/routes/helpers.ts` — shared `currentEmployee` (Bearer → employee) used by
  employee + github route modules.
- `server/src/routes/github.ts` — `POST /api/me/github-credential` (register/update own
  credential, never echoes the value) + `GET /api/github/repos` (401 no session / 400 no
  credential / 200 repos scoped to the signed-in user).
- `server/src/routes/employees.ts` — `POST /api/employees` accepts optional `github_credential`
  (registration-time), validated then encrypted by the registry.
- `server/src/app.ts` — `defaultSecretCipher()` (ENCRYPTION_KEY, dev-only fallback),
  `defaultGithubClient()`; `buildApp` wires `cipher` + `github` + `registerGithubRoutes`.

Tests (RED→GREEN): `server/test/crypto.test.ts` (6), `employees.test.ts` (+5 incl. PG
at-rest integration — raw column holds ciphertext, decrypts back), `github-client.test.ts` (5),
`github-routes.test.ts` (8: per-user scoping + never exposes the credential). `npm test` 273
pass / 0 fail; `npm run typecheck` clean. Verified against real Postgres (athena_test).

Acceptance criteria met: credential encrypted at rest (PG integration proves ciphertext not
plaintext), scoped repos API per signed-in user, per-user visibility via that user's token.
