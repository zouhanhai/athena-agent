## Context

The AgentIDE vision: users manage remote agents from the platform. The decided connectivity model
(2026-08-15) is **reverse WebSocket**: the agent actively connects INTO the platform's WS server
(outbound, works behind NAT/CGNAT, no public IP, no admin), and the platform drives the agent back
through that tunnel. This replaces the earlier HTTP+SSE-only design. Depends on T2 (agent registers with
api_url/token + capabilities).

## Task

1. **Platform WS server**: expose a WebSocket endpoint that remote agents connect INTO (outbound).
   - Agent initiates the connection + registers `{agent_id, token}` (auth'd, per T2).
   - On connect, platform records the agent as reachable + keeps the tunnel.
2. **Bidirectional**: platform pushes tasks/commands to the agent through the tunnel; agent streams
   `tool.started` / `tool.completed` + result deltas back.
   - Hermes agent tasks: `POST /v1/chat/completions` (SSE) — driven over the connection.
3. **Behind NAT**: agent connects outbound (no public IP / no inbound port); platform reaches it via the
   established tunnel. Handle disconnect/reconnect (agent re-connects, resumes).
4. **Chat panel**: route a chat to a selected registered agent; stream tool progress + result into the
   panel (uses the reverse connection).
5. **Tests**: server (WS endpoint, bidirectional, reconnect, auth) + web (agent selector + progress rows).

## Acceptance

- Platform WS server accepts agent-outbound connections; agent registers + stays connected.
- Bidirectional: platform pushes tasks, agent streams tool.started/completed + results back.
- Works behind NAT/CGNAT (no public IP). Reconnect handled. Tests green, typecheck clean, live on 6900XT.

## Notes
