## Context

The AgentIDE vision: any agent (OpenCode/Claude Code/Codex/Hermes) can retrieve the company KB. This
ticket wraps the existing KnowledgeRetrievalService into an **MCP server** (search_knowledge /
get_wiki_page / get_graph), documents the **topic-scoped search contract** (the Spec's critical
contract so external agents retrieve correctly), auth'd over the platform's public URL. Independent of T2/T4 — can
proceed in parallel.

## Task

1. **Add MCP SDK**: install `@modelcontextprotocol/sdk` (server + server/node_modules or gdd/).
2. **Build the MCP server**: wrap KnowledgeRetrievalService into tools:
   - `search_knowledge(query, topic?)` — topic is a wiki frontmatter topic subtree (e.g.
     `internal/events`, `sap`, `sap/group_reporting`); omit/empty = whole-corpus. Teach the tool
     description: "if the question is about a specific domain, pass its topic subtree; otherwise omit."
   - `get_wiki_page(path)` — read a wiki page's content + frontmatter.
   - `get_graph()` — knowledge-graph nodes/edges.
   - Retrieval results carry `wikiPath`/`sectionPath`.
3. **Alias handling**: apply alias mapping (G3.S2.T6) + bilingual aliases (G2.S2.T1) at query time within
   the scoped topic.
4. **Auth**: MCP server auth'd (per-employee/agent token); document that agents reach it over the
   platform's public URL (Cloudflare Tunnel).
5. **Document the contract**: topic-scoped search contract in the S7 spec + MCP tool descriptions so any
   client agent retrieves correctly.
6. **Tests**: server tests for the MCP tools (search/get_wiki/get_graph + topic scoping + alias).

## Acceptance

- MCP server exposes the 3 tools wrapping KnowledgeRetrievalService; retrieves correctly with topic scoping.
- Contract documented (topic subtree, agent chooses domain, omit = corpus). Results carry wikiPath/sectionPath.
- Aliases applied. Auth'd over the public URL. Tests green, typecheck clean.
