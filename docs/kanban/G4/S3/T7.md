## Background

These need an LLM in the retrieval/generation path (deviate from S2's pure-storage lean design)
(G4.S3, added 2026-08-11, from docs/retrieval-analysis.md).

## Task

1. **Query Transformation**: if a question is too broad, ask back for detail; or decompose the query
   into multiple sub-queries and run them in parallel, then fuse.
2. **Compression**: after recall, an LLM distills the retrieved chunks into a concise summary before
   output — controls token use and removes noise.
3. **Agentic retriever picker**: the LLM picks the best retriever (vector/bm25/graph/hybrid) per query
   (ToolsRetriever exists, defaults to "hybrid" — make the LLM pick).
4. **Topic convergence (integrate G4.S3.T4 topic-scoped search)**: as part of picker, the LLM also
   decides the relevant **topic subtree** for the question (topic = Athena's knowledge-navigation:
   determine topic → converge document domain → search within it), then passes it to the topic-scoped
   retriever so retrieval is scoped to that domain. Omit topic for whole-corpus when the question is
   cross-domain/ambiguous. This is the retrieval-side of the KB-as-MCP `search_knowledge(query, topic?)`
   contract (G4.S6).
5. **Multi-hop graph reasoning**: the LLM walks the Entity/Relation graph over multiple hops to discover
   indirect associations the single-hop retriever misses.
6. **Not-found handling + web fallback (added 2026-08-12)**: when the KB retrieval returns nothing
   relevant (LLM judges the hits don't answer the question), Athena should:
   - Say explicitly "not found in the knowledge base" (no hallucination / no off-topic answer).
   - **Web search fallback**: Athena has network search — use it to answer (and/or to compare against
     the KB's partial results).
   - **Suggest KB update**: compare the KB result vs the web result and tell the user *what*
     knowledge the KB is missing / should be added/updated (e.g. upload the doc, the topic domain).
   - This needs a `web_search` tool on the Athena chat agent (verify Pi SDK support; if the SDK
     doesn't expose one, add a thin wrapper that calls the platform's search provider).
7. Uses Athena/the LLM channel; injectable/optional so it can fall back to non-agentic retrieval.
8. TDD each; server tests green + typecheck clean.
