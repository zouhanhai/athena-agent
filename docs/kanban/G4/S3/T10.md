# G4.S3.T10 — Wiki edit → Athena diff-refine → RAG re-ingest

## Context

A document may contain a VLM image description that mis-reads a word (an OCR/vision error). The wiki
page is currently **read-only** (WikiView has no save API) and there is **no mechanism** to push a wiki
edit back into the RAG store. A correction made in the wiki would not be reflected in retrieval, and
could also miss NEW entities/relations the correction implies.

Goal: let a user fix the text in the wiki, then have **Athena** re-examine the change and re-ingest the
affected document into RAG so both the corrected text AND any newly-introduced entities/relations are
reflected — without re-running the whole docling/refine-from-scratch pipeline.

## Design (user-approved direction)

```
User edits wiki page  (fixes a VLM mis-description)
  → Save: snapshot BEFORE + AFTER  → versioned diff (knows exactly what changed)
  → Athena incremental refine (input = corrected wiki + the diff):
        • PRESERVE the corrected text (never rewrite the manual edit)
        • Compare BEFORE vs AFTER: detect NEW entities / relations / changed section structure
        • Decide whether re-chunking is needed (edit localized vs structural)
  → Re-ingest the document into RAG (overwrite the old version):
        • Locate old version via wikiPath → Document → Chunk(s)
        • Remove stale chunks / sections / entity-mention edges for this document
        • Embed the (possibly re-chunked) corrected text; MERGE new entities/relations
```

Key points:
- **Not from docling.** The input is the already-refined wiki, not raw docling output.
- **Diff-aware.** Athena is told what changed (before vs after) so it analyses only the edited region —
  faster, more accurate, and it knows the correction is intentional (does not "fix" it back).
- **Preserve manual edits.** The corrected text is the source of truth; Athena adds structure (chunks,
  entities, relations), it does not rewrite prose.
- **Overwrite via wikiPath.** `WikiPage {id: wikiPath} -[:IS_DOCUMENT]-> Document -> (Chunk|Section)`
  gives the exact nodes to replace. Remove the old doc's chunks/edges, then insert the new ones.
- **Versions are transient, not stored.** The BEFORE/AFTER diff is only scratch data for Athena's
  analysis. Once the re-ingest completes, ONLY the corrected version remains — in the wiki file AND in
  the RAG store. The old wiki file and old Neo4j chunks are deleted, not kept as history. No version
  stack is retained (correctness of the current doc is what matters, not revision history).

## Task

1. **Front-end wiki editing** (`web/src/views/WikiView.vue`):
   - Make the page editable (textarea/editor toggle), default read-only; Save per page.
   - Send the edited markdown to a backend save API.

2. **Backend save + version diff** (`server`):
   - Save API: write the new markdown to the wiki dir + rebuild index. Keep the pre-edit content to
     compute the diff (`wiki-frontmatter`/write-through for metadata).
   - Build a minimal diff (changed lines/region) passed to the Athena incremental refine.

3. **Athena incremental refine mode** (`server/src/agents/refine-document.ts`):
   - A new mode (not the full `refine_document` from docling): input = corrected markdown + the diff.
   - Prompt: "the user corrected THIS text (show diff). Preserve it. Compare before/after. Extract any
     new entities/relations the correction introduces; decide if the change forces re-chunking. Do NOT
     rewrite the prose." Emit the (corrected) markdown + updated chunks + entities/relations + quality.

4. **Re-ingest / overwrite** (`server/src/kb/tasks.ts` + `store/ingest.ts`):
   - Locate `Document`/`WikiPage` via `wikiPath`.
   - Delete the old document's `Chunk`/`Section`/`Entity-[:MENTIONED_IN]`/relation edges for that doc
     (idempotent; reuse the per-chunk progress callback from G4.S3.T9).
   - Embed the corrected chunks (qwen3-embedding) and MERGE new Document/Chunk/Entity/Relation nodes.
   - Task status surfaced in the UI (reuses the ingest task model / live timer + ETA from T9).

## Acceptance

- Wiki editable + save persists (read-only default, opt-in edit).
- Save triggers Athena diff-refine that preserves the correction and picks up new entities/relations.
- Re-ingest overwrites the old RAG version (via wikiPath), stale chunks removed, retrieval returns the
  corrected text.
- Localized edits avoid a full re-chunk when structure is unchanged.
- Tests: web wiki-edit/save + save API; server diff-refine + overwrite re-ingest + new-entity detection.
  Suites green + vue-tsc clean.
