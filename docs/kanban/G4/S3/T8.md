## Background

The old LightRAG track poller showed chunk progress (X/Y) during ingest. The self-built Neo4j store
(T4/T10) lost this: `OpenRouterEmbedder.embed()` is a single await that batch-processes internally
(batchSize=64) but returns only after ALL chunks are embedded, and Neo4j ingest writes only after the
full embed completes. So the Uploads page shows a single "Neo4j (RAG): done" with no in-progress X/Y.

For large docs (1000+ chunks) the embed can take a while — the user wants to see how many chunks are
done and an ETA.

## Task

1. **Embedding progress callback**: extend `OpenRouterEmbedder` (and `TextEmbedder`) with an optional
   `onBatch?: (done: number, total: number) => void` that fires after each internal batch (64) so a
   caller can observe progress. Keep backward-compatible (callback optional).
2. **Ingest write-through per batch**: `Neo4jIngestService.ingest` should embed + write chunks in
   batches, reporting `{ done, total }` after each batch (via a progress callback or a `(progress) => void`
   option), instead of waiting for the whole embed then writing everything.
3. **Task stage progress**: the `ingesting_neo4j` stage exposes `chunksStored`/`chunksTotal` (and a
   progress 0..1) on the task, updated as batches complete, so the API `/api/kb/task` returns it.
4. **Frontend**: the Uploads page Neo4j (RAG) stage shows `X / Y chunks` and an ETA (estimated from
   per-batch rate) while running; on completion shows `Y chunks`.
5. **TDD**: embedder fires onBatch; ingest reports incremental progress; task + API surface expose it;
   web shows X/Y + ETA.
6. Server + web tests green, typecheck clean.

## Acceptance
