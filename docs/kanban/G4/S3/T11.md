## Context

Today Settings is a flat page with Profile + Agents. There is no admin-specific surface, and no way in
the UI to grant permissions (e.g. the new `kb.edit` from G4.S3.T10) or generate invites — those exist
only as backend APIs (`POST /api/invitations`, `GET/POST /api/employees`, `PUT /api/employees/:email`).

Goal: a dedicated **Admin console** reachable from the sidebar, visible **only to admins**, with two
management areas: an **employee list** (role + `kb.edit` switch per row) and **invite-link generation**.

## Task

1. **Sidebar conditional nav** (`web/src/components/SidebarNav.vue`):
   - Make `navItems` reactive; append an **Admin** item (`/admin`) only when the signed-in employee has
     `role === "admin"` (from the auth store). Members never see it. Place it near Settings.

2. **Admin page** (`web/src/views/AdminView.vue` + route `/admin`), two areas:
   - **Employee list** (single area — expandable two-level rows):
     - Top-level row per employee: email, display_name, logo, role, `kb.edit` switch.
     - Per row: a **role** control (admin ↔ member) via `PUT /api/employees/:email`.
     - Per row: a **`kb.edit` switch** (grant/revoke) — stored on the employee, backed by the same
       update endpoint (or a small dedicated permission endpoint if cleaner). Server enforces admin-only.
     - **Second level**: clicking/expanding an employee reveals the **agents they own** (alias + logo,
       grouped by `AgentRecord.owner_employee_id`). `GET /api/agents` already carries the owner — group
       by owner. An admin sees at a glance which agents each employee invited/owns.
   - **Invite generation**:
     - Input an email → `POST /api/invitations`.
     - **Backend change**: today `invite()` returns `{ ok: true }` and only prints the link via
       ConsoleMailer (email not configured). Make `POST /api/invitations` (or a companion
       `GET /api/invitations/link`) return the **generated invite URL** so the frontend can render a
       copy-able link. The existing ConsoleMailer log stays as a fallback.
     - Frontend shows the link with a **copy** button; TTL noted (existing 7-day default).

3. **Routing + guard**: `/admin` route; a navigation guard (or in-page check) redirects non-admins away.

## Acceptance

- Sidebar Admin entry only for admins.
- Admin page = employee list (with role + `kb.edit` per row) + invite generation. No extra sections.
- Server rejects non-admin calls (RBAC); UI hides admin controls for members.
- Tests: web sidebar-conditional + admin-view (list/role/kb.edit-switch/invite); server permission grant
  if a new endpoint is added. Suites green + vue-tsc clean.
