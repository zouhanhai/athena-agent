## Background

On the Chat page, a user can upvote/downvote an answer. This feeds the KB lifecycle (G4.S3, added
2026-08-11).

## Task

1. Add a feedback control on the Chat answer (thumbs up/down).
2. Backend: store Q&A pairs `{question, answer, sources, feedback}` in a DB table (reusable, avoids
   re-RAG for the same question).
3. **Q&A dedup on store (added 2026-08-12)**: before inserting a new Q&A pair, vector-search the
   existing Q&A store for a semantically similar question (embed `question` with the same embedder —
   `qwen/qwen3-embedding-8b` — and query the Q&A vector index, same threshold approach as chunk
   dedup). If a similar question exists (score ≥ threshold), **update that existing pair** (aggregate
   the new feedback / append the new answer) instead of inserting a duplicate.
4. Upvote = reinforce → raise `confidence` of the source chunks/document.
   Downvote = fade → lower `confidence` (via the canonical `updateWikiFrontmatter` syncer so wiki +
   Document mirror stay in sync).
5. TDD: feedback stored (with dedup — similar question updates, new question inserts); confidence
   updated per feedback direction.
6. Server + web tests green, typecheck clean.

## Acceptance

- Chat shows thumbs up/down; Q&A pairs stored (deduped by vector similarity); confidence reacts to
  feedback.
