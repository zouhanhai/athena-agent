## Background

Agentic RAG (G4.S3.T7) was implemented (`AgenticRetrievalService`, `createSearchKnowledgeTool`, `AgenticJudge`, `DuckDuckGoWebSearchProvider`) but **never wired into the production chat agent**. In `server/src/agents/agent.ts`, `createSearchKnowledgeTool(options.agenticRetrieval)` only registers when `agenticRetrieval` is passed — and `AgentManager`/`buildApp` never pass one. So the Athena chat agent only has the 3 llm_wiki tools (`wiki_search`, `wiki_read_page`, `wiki_graph`) and NO `search_knowledge`.

Consequence (observed): asking "what is caleo" falls back to web, the stored Q&A pair (`qa_pairs` + Neo4j `QaPair`) is never reused, and the agent even reports "MCP not initialized / no search_knowledge access".

Also confirmed: `AgenticRetrievalService` is only constructed in tests, never in production (no `new AgenticRetrievalService` in `server/src` outside tests).

## Task

1. **Wire agentic RAG into `server/src/agents/agent.ts`** (`createAgent`):
   - When `options.agenticRetrieval` is not supplied, build a default `AgenticRetrievalService`:
     - `search`: the KB retrieval search (use the retrieval service the app wires, or construct a `KnowledgeRetrievalService` with the default Neo4j driver + llm_wiki + semantic mappings + QA reference — see `defaultRetrievalService()` in `server/src/app.ts` and the `KnowledgeRetrievalService` ctor in `server/src/kb/retrieval.ts`).
     - `judge`: `createAgenticJudge(modelRuntime)` (the modelRuntime already exists inside createAgent).
     - `webSearch`: `new DuckDuckGoWebSearchProvider()`.
     - `topics`/`graph` if available from the retrieval service.
   - Register `createSearchKnowledgeTool(agenticRetrieval)` so `search_knowledge` is exposed.
   - Best-effort: on wiring failure, log and continue without the tool (never crash agent creation).
   - Prefer wiring in `createAgent` over `buildApp` so the judge reuses the existing per-session `modelRuntime` and it works for any caller.

2. **Verify the retrieval service exposes what agentic RAG needs**:
   - `KnowledgeRetrievalService` must provide `search`, `topics`, `graph` (or the agentic service must map them). Check `server/src/kb/retrieval.ts` for the exact public surface; add `topics()` / `graph()` accessors if missing.
   - The retrieval search already returns `qaReference` (stored Q&A) — confirmed folded into hits by G4.S3.T10-era fix in `agentic-rag.ts` (`response.qaReference` → hit). Ensure the default wiring sets up `qa` + `mappings` on the retrieval service (see `buildApp` at `server/src/app.ts` lines ~381-395 which passes `mappings` and `qa: feedback`).

3. **Tests** (`server/test/kb/agentic-rag.test.ts` + a createAgent-level test):
   - `createAgent` (with a fake/stub retrieval or mocked modelRuntime) registers the `search_knowledge` tool.
   - A stored Q&A pair is reused (already covered by the qaReference→hit test; add an end-to-end assertion if cheap).
   - Existing agentic-rag tests keep passing.

## Notes / gotchas

- Do NOT hard-code a Neo4j password in source — read from `NEO4J_URI`/`NEO4J_USER`/`NEO4J_PASSWORD` env (see `neo4jConfigFromEnv` in `server/src/kb/store/driver.ts`).
- The `athena` provider (auth.json) powers the judge — reuse the same `modelRuntime` instance created inside `createAgent`.
- Keep it additive; don't remove the llm_wiki tools.
