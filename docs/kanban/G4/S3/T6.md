## Background

A new dedicated tab "Terms & QA" shows semantic mappings (custom synonyms) and stored Q&A pairs, with
live query against the DB and manual Q&A entry (G4.S3, added 2026-08-11).

## Task

1. **Semantic mappings**: front-end to view/add/delete company-term → canonical mapping (e.g.
   "C-Day" → "CALEO Day"). Stored in a DB table; applied at query time so a colloquial term also
   matches the canonical. Complements T1 Athena aliases (DE/EN) with user-curated mappings.
2. **Q&A pairs**: the tab lists stored Q&A pairs (from the feedback loop + manual), with **live query**
   against the DB.
3. **Manual entry**: the tab lets a user type in a Q&A pair directly (knowledge injection). The
   manual add **reuses the T5 vector-dedup** (`QaEmbeddingIndex`): before insert, vector-search the
   existing Q&A for a similar question; if one matches, the front-end shows "similar Q&A exists"
   and lets the user choose merge/overwrite/add-anyway (keep the Q&A store deduped across both the
   feedback loop and manual entry).
4. **Search integration (added 2026-08-12)** — the search path MUST consume the T6 data:
   - **Term query expansion**: at search time, look up the semantic-mapping table and expand the
     query's colloquial terms into their canonical form (e.g. "C-Day" → "CALEO Day"), so BM25/vector
     recall the canonical text. Expansion feeds both the Neo4j search and llm_wiki keyword search.
   - **QA lookup as reference (NOT a short-circuit)**: vector-search the QA store for a similar
     question; if one matches, pass the stored answer to the LLM as **reference context only** —
     do NOT return it directly (the KB may have newer knowledge). The RAG search always runs and the
     LLM grounds its answer on the latest retrieval + the QA reference.
5. New sidebar tab "Terms & QA".
6. **One-to-many semantic mappings (added 2026-08-12)**: a term can map to MULTIPLE canonical
   forms (e.g. `EDay` → `Expert Day`, `Principle Day`). Changes:
   - Schema: `semantic_mappings.canonical` becomes a TEXT array (`canonical TEXT[]`), or the term
     stores a canonical list.
   - Input: the front-end accepts canonical as comma/`/`-separated values → stored as an array.
   - `expandTerms` (query expansion): a matched term expands to its canonicals joined as an OR
     alternative (e.g. `EDay` → `(Expert Day OR Principle Day)`), so BM25/vector recall any of them.
     Backward-compatible: a single canonical still expands plainly.
7. **Fuzzy term variant matching (added 2026-08-12)**: `expandTerms` must match a term regardless of
   spacing/hyphenation — `CDay` matches `CDay`, `C Day`, `C-Day` (normalize by removing spaces +
   hyphens, case-insensitive). Implementation must map the normalized-match offset back to the ORIGINAL
   query to replace the correct span. Update the `semantic-mappings` tests for these variants.
8. TDD: CRUD for semantic mappings (one-to-many + variant matching) + Q&A pairs; live query; manual add
   (with dedup); **search applies term expansion (incl. one-to-many OR + variant matching) + QA reference**.
   Web + server tests green, vue-tsc + typecheck clean.
