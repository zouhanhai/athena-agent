## Background

Knowledge has a lifecycle (LLM Wiki v2): some facts are fresh, others stale. The wiki frontmatter is
the natural place to carry confidence + lifecycle (G4.S3 core).

## Task

1. Extend the wiki page frontmatter schema (ingest/llmwiki frontmatter writer) with:
   - `read_count` (int, times Athena/retrieval read this page)
   - `last_reviewed` (ISO date, last Athena KB review)
   - `confidence` (float 0..1, decays over time)
   - `topic_history` (ordered list of past topics — migration audit trail)
   `created`/`updated` already exist.
2. **Bidirectional sync with RAG**: the same lifecycle fields must ALSO be stored on the Neo4j
   `Document` node (it already carries topic/type/summary shared with the wiki frontmatter, and links
   to the wiki via `WikiPage`/`IS_DOCUMENT`). The frontmatter is the source of truth on disk; the
   Document node mirrors it so retrieval can rank by confidence and the KB review can act on it.
   - Document node gains `read_count`, `last_reviewed`, `confidence`, `topic_history`.
   - Write-through: when the wiki frontmatter updates (review/re-topic/feedback), the Document node
     mirrors the change.
3. Increment `read_count` on BOTH the wiki frontmatter AND the Document node when the retrieval
   service surfaces the page.
4. TDD: frontmatter writer emits the new fields; Document node mirrors them; read_count increments
   on both.
5. Server tests green + typecheck clean.

## Acceptance

- Frontmatter carries the 4 new fields; Document node mirrors them; read_count increments on both.
