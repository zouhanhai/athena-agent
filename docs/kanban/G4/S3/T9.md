# G4.S3.T9 — Uploads live elapsed timer + RAG chunk progress ETA

## Context

The Uploads task info bar shows `formatDuration(task)` = `updatedAt - createdAt`, which is `0s` right
after a task starts (the backend only touches `updatedAt` on each poll, ~1.5s) and never ticks live.
Also, during the Neo4j/RAG stage there is no "how much longer" estimate, only a final
`chunk_count`/`chunks embedded` after the fact.

Goal: (1) a **live elapsed timer** that ticks every second from `createdAt`; (2) during the RAG stage,
a **per-chunk ETA** (remaining chunks × rolling avg ms/chunk) that updates as chunks embed.

## Task

1. **Server — per-chunk progress during Neo4j ingest** (`server/src/kb/store/ingest.ts`):
   - `storeNeo4j` (or the embed loop) accepts an optional `onProgress?(processed: number, total: number): void`
     callback, invoked after each chunk is MERGE'd + section-linked.
   - `server/src/kb/tasks.ts`: pass an `onProgress` that updates the `ingesting_neo4j` stage step
     (`embed_store`) with a live `progress` string like `"embed_store: 5/16"` and sets a rolling
     `etaMs` on the task when total>0. Keep the existing final `chunksStored` behavior.
   - `IngestTask`/stage type: add optional `processed`/`total` (or a `progress` text) + `etaMs` so the
     frontend can read it. This is additive — don't break existing fields/consumers.

2. **Web — live elapsed timer + ETA** (`web/src/views/UploadsView.vue`):
   - Add a `now` ref updated by a `setInterval` (~1s) while the view is mounted (clear on unmount).
   - Replace the frozen `formatDuration(task)` (uses `updatedAt`) with a live `elapsed(task)` computed
     from `Date.now() - task.createdAt`, re-rendered by `now`. So it ticks even between polls.
   - During the RAG stage (`task.stages.ingesting_neo4j.status === "running"`) and when the server gives
     `processed`/`total`, show an **ETA** line: `~ Nm Ns left` from `(total - processed) * avgMsPerChunk`
     where `avgMsPerChunk` is a rolling average of the elapsed vs processed. Recompute as `now` ticks.
   - Before RAG (parsing/refinement) show only the live elapsed time — no ETA (no per-chunk baseline yet).

3. Keep the existing info-bar content (`Type/Topic/Accepted/N chunks/N entities`). The timer is appended.

## Acceptance

- Uploads note ticks live (1s) from the start; never frozen at 0s.
- During RAG it also shows a decreasing ETA based on real chunk progress.
- Parsing/refinement show elapsed only.
- Tests: server `store/ingest` onProgress callback + task `etaMs`/`processed/total`; web `uploads-view`
  live timer + ETA rendering. Web + server suites green, vue-tsc + typecheck clean.
