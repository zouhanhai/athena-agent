## Context

The agentic RAG plan step (`AGENTIC_PLAN_SYSTEM_PROMPT` in `server/src/kb/agentic-llm.ts`) tells the
judge to choose `clarify` when the question is "too broad / ambiguous". In practice this fires on
**definitional/entity questions** like "what is caleo" — the judge sees "caleo" could be a person,
a company, a Latin term, etc., returns a clarify, and `AgenticRetrievalService.answer()` (lines
~171–179) swallows it into a plain answer ("Are you referring to a person, a company/product...?").
This is wrong on two counts:

1. **A user asking "what is X" is BY DEFINITION unfamiliar with X** — they cannot answer a
   clarifying question ("do you mean person or company?"). Clarifying is a dead end for exactly the
   users who need the answer. The correct behaviour is to **search the KB and answer** (ideally
   reusing a stored Q&A pair like "what is CALEO?" → "CALEO ist eine ... Unternehmensberatung"),
   optionally noting the ambiguity alongside the answer.
2. **Even when a clarify is legitimate** (question with NO extractable subject, e.g. "help me with
   something"), the current implementation returns the clarification text as the final `answer` — the
   user never gets a real follow-up they can act on, and the answer is not fed back to re-run the
   query.

This ticket fixes both: the trigger condition, and surfacing a real clarification interaction.

## Task

1. **Fix the trigger** (`server/src/kb/agentic-llm.ts` — `AGENTIC_PLAN_SYSTEM_PROMPT`):
   - Reword so `clarify` is chosen ONLY when the question has **no extractable subject / object**
     (no entity or thing to look up), e.g. "help me with something", "what should I do about this".
   - Explicitly: definitional/entity queries ("what is X", "who is X", "what is caleo", "what is RAG")
     → choose `direct` (search the KB) even if X is ambiguous; ambiguity is handled by answering with
     the most-likely interpretation + a note, NOT by clarifying.
   - Keep `decompose` and `direct` semantics otherwise unchanged.

2. **Carry a clarify signal through the tool contract**:
   - `AgenticRetrievalService.answer()` already returns `AgenticAnswer` with `notFound`/`webResults`.
     Add a field to signal a real clarification request (e.g. `needsClarification?: boolean` +
     keep `plan.clarification` text), so callers can distinguish "here is a question for the user"
     from a normal answer.
   - `createSearchKnowledgeTool` (`server/src/kb/tools.ts`) should surface that signal in its result
     (e.g. a structured field or a clear marker) so the agent knows this is a clarification to ask the
     user, not a final answer.

3. **Real user follow-up**:
   - Backend: when the agent decides to clarify, the answer returned to the chat should carry the
     clarification question distinctly. Work out the minimal contract (e.g. `search_knowledge` returns
     `clarification: "<question>"`; the agent turns it into a prompt back to the user, or the chat
     route renders a clarification affordance). Do not silently return it as a normal paragraph.
   - Frontend (`web/src/stores/chat.ts` + `web/src/components/GlobalChatPanel.vue`): detect a
     clarification from the assistant message (by a structured SSE field or a well-defined marker),
     render it as a **clarification affordance** (the question + optional suggested options), and when
     the user answers, **re-run the query with the user's clarification appended as context**.
     The conversation must keep working (user answer becomes a follow-up message).

4. **Tests**:
   - Server: agentic-rag answer returns `needsClarification` for a no-subject query, and does NOT
     clarify for "what is caleo" (search runs, QA pair reused). Plan prompt is covered by a seeded
     judge test if cheap.
   - Web: chat store surfaces a clarification + re-runs the query with the user's answer.
   - Existing agentic-rag / chat tests keep passing.

## Acceptance

- "what is caleo" (and "what is RAG") answer from the KB, not a clarify dead-end.
- Clarify only for genuinely subject-less queries.
- A legitimate clarify is shown to the user as a real follow-up; the user's answer re-runs the query.
- Server + web suites green, typecheck/vue-tsc clean.
