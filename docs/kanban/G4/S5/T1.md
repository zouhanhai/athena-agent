## Context

G4.S5 maps the local md kanban (Goal → Spec → Ticket, source of truth) onto GitHub Projects v2
(decision 2026-08-13):
- **Project v2** = one repo's kanban board
- **Goal** = GitHub Milestone + a Label (`G4`)
- **Spec** = a main Issue (title `Gx.Sx <title>`, body = design doc, comments = team discussion)
- **Ticket** = a sub-issue (title `Gx.Sy.Tz`, status → Project Status column, blocked_by → issue dependency)

The current `GithubRestClient` is REST-only; **Projects v2 is GraphQL-only**, so this ticket adds a
GraphQL layer (and the missing REST `createIssue`) as the foundation for the S5 sync (T2/T3).

## Task

1. **GraphQL client** (`server/src/github/graphql.ts`):
   - A thin `GithubGraphqlClient` posting to `https://api.github.com/graphql` with the employee's
     token (`credential.type === "token"`), reusing `GithubAuthError` + error conventions.
   - Helper `gql(query, variables)` that throws on `errors`.

2. **GitHubApi additions** (interface + impl, REST where possible, GraphQL where required):
   - `createIssue(credential, owner, repo, {title, body, labels})` — REST `POST /issues` (missing today).
   - `createSubIssue(credential, owner, repo, parentIssueNumber, {title, body})` — GitHub
     sub-issue (issue relationship). Verify the exact API in the GitHub docs; it may be REST
     (`POST /repos/{o}/{r}/issues/{n}/sub_issues`) — check the version.
   - `getIssueByTitle(credential, owner, repo, title)` — find a Spec/Ticket issue by its `Gx.Sy` title
     (for idempotent create/sync).
   - `addLabel(credential, owner, repo, issueNumber, label)`, `setMilestone(...)`.
   - Project v2: `createProject`, `getProjectByTitle`, `addIssueToProject`, `getProjectItems`,
     `setItemStatusField` — all GraphQL.

3. **Status mapping** (`server/src/kanban/github-sync.ts` or a `status-map.ts`):
   - kanban status (`backlog`/`in_progress`/`done`/`in_review`/`approved`/`rejected`) → Project
     Status single-select option names, and the inverse.

4. **Tests** (`server/test/kanban-github-sync.test.ts`): mock the GraphQL/REST clients; assert each
   new operation builds the right query/payload; assert status mapping. Server tests green +
   typecheck clean.
