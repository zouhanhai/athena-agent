## Context

A repo can have MULTIPLE linked Projects (e.g. `zouhanhai/athena-agent` has `@zouhanhai's untitled
project` (closed, accidental) and `zouhanhai/athena-agent` (open)). T11's endpoint takes `projects[0]`,
which may be a CLOSED project, so the frontend shows the wrong/empty board. The user (2026-08-13) wants
a PROJECT SELECTOR in the GitHub Project view so they can choose which linked project to display, and
closed projects should not appear.

## Task

1. **`getRepoProjects`** (`server/src/github/graphql.ts`): filter out closed projects — query
   `repository(owner,name){ projectsV2(first:100){ nodes{ id title number url closed } } }` and return
   only `!closed` ones.

2. **Backend** (`server/src/routes/kanban.ts`):
   - `GET /api/kanban/github-projects?repo=OWNER/REPO` → `{ projects: [{id,title,number,url}] }` (open
     linked projects) for the selector.
   - `GET /api/kanban/github-project?repo=OWNER/REPO&project=<id>` → serves the specified project; when
     `project` is absent, serve the first open project. Keep 404 when no open project.

3. **Frontend** (`web/src/components/KanbanTab.vue` + `web/src/api/kanban.ts`):
   - Fetch the open project list; render a PROJECT SELECTOR (TDesign select/dropdown) above the board.
   - Default selection = first open project (or remember the last chosen via a ref/localStorage).
   - On change, fetch + render that project's board.

4. **Tests**:
   - Server (`server/test/kanban-routes.test.ts`): getRepoProjects returns only open projects; the
     github-project endpoint serves a specified project or the first open one.
   - Web (`web/src/__tests__/kanban-tab.spec.ts`): the selector lists open projects, switching loads the
     chosen board, closed projects absent.
   - Server + web tests green, typecheck/vue-tsc clean.
