## Context

The Kanban Project detail panel (opening a card in the GitHub view) currently renders the LOCAL md
(`detailMd` from `parseTicketMd`), which includes the Progress Log. The Issues panel renders the GitHub
issue body (no Progress Log — it is stripped from GitHub sync). The user (2026-08-14) wants consistency:
**both issue-detail entry points (Issues panel AND Kanban Project) read the GitHub ISSUE BODY**; the
Progress Log stays in md only (backend/dev), never shown in any frontend issue detail. So the Kanban
detail must fetch + render the GitHub issue body instead of the local md, and stop showing Progress Log.

## Task

1. **Fetch the GitHub issue body** (`web/src/api/kanban.ts`): add a `fetchGithubIssueBody` (or extend the
   existing fetch) that GETs the issue by number from the repo and returns `{ title, body, ... }`.

2. **Kanban detail renders GitHub body** (`web/src/components/KanbanTab.vue`):
   - When a card/sub-issue opens, fetch the GitHub issue body (in addition to the existing
     `fetchGithubIssueComments`); render `detailIssue.body` via `renderMarkdown`.
   - Replace the local-md description / Progress Log rendering with the GitHub issue body.
   - Remove the Progress Log rendering (the `detailMd.progressLog` list) — Progress Log is no longer shown
     in any frontend detail.
   - Keep the sub-issues list + comments (unchanged sources).

3. **Tests** (`web/src/__tests__/kanban-tab.spec.ts`):
   - Assert the Kanban detail renders the GitHub issue body, not the local md.
   - Assert no Progress Log is rendered in the detail.
   - Web tests green + vue-tsc clean.

## Acceptance

- Progress Log not shown in any frontend issue detail (md-only).
- Sub-issues + comments still work.
