## Context

T1/T2 built the **md → GitHub projection**. This ticket closes the loop: **GitHub → md**. On a
multi-person project, the team discusses on Issue comments; the **plan agent** reads new info and turns
it into md updates (new/edited ticket, or a new spec via the existing `planning.ts` grill→to-spec→
to-ticket flow). md stays authoritative; human keeps final authority on conflict. This is the feedback
loop of the Greenfield team-collaboration flow:
Chat discussion → plan agent builds md → sync to GitHub Project → worker executes → issue discussion →
feedback into md.

## Task

1. **Feedback reader** (`server/src/kanban/github-feedback.ts`):
   - `listIssueComments` (already on GitHubApi) + **dedup**: track seen comment IDs in a
     `docs/kanban/Gx/Sy/sync-state.json` (or a frontmatter field) so the plan agent only processes new
     comments.

2. **Plan-agent reconcile path**:
   - A function that presents new issue comments + the current md state to the plan agent and lets it
     propose md updates (new/edited ticket, new spec). The proposal is rendered as a **draft**, NOT
     applied silently. Reuse `planning.ts` (PlanInput → planGoal) for new Goal/Spec/Ticket generation.
   - Wire into the plan agent flow (`server/src/kanban/planning.ts` or a new module).

3. **Conflict handling (md authoritative)**:
   - When a sync would overwrite md with GitHub-derived state, do NOT write silently. Surface a
     diff/report (log or a `conflicts` list in the sync tool output) for the plan agent to reconcile.
     md never auto-loses.
   - Document: GitHub changes are advisory; md wins on conflict; human confirms.

4. **CLI extension** (`server/scripts/sync-github.ts`): add `feedback <specRef>` — pulls new comments,
   shows the plan-agent proposal for review (no auto-apply).

5. **Tests** (`server/test/kanban-github-sync.test.ts`): mock GitHub; assert comment dedup (seen vs
   new), proposal generation via planning.ts, and that conflicting md is never silently overwritten (a
   report is produced instead). Server tests green + typecheck clean.

## Acceptance

- Plan agent reads new Issue comments (deduped) and proposes md updates (new ticket/spec).
- Proposals are drafts, not silent writes.
- md authoritative: conflicts surface as a report, never auto-overwritten.
- CLI `feedback` command works.
- Tests green, typecheck clean.
