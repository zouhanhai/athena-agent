## Context

T6 made the board show one Spec card per Spec with a segmented progress bar. The user (2026-08-13)
reviewed the Workbench GitHub Project view and wants three refinements to the detail panel that opens
when clicking a Spec card:

1. **Show sub-issues**: the detail panel currently shows only the Spec md content + GitHub comments. It
   should ALSO show the Spec's sub-issues list (T1-T4: ref + title + status + progress), clickable to
   open each sub-issue's own detail (like GitHub's Sub-issues block).
2. **Don't cover the Chat**: the detail panel is currently `position: fixed` full-screen overlay
   (`kanban-detail-overlay` with `inset: 0`), which covers the fixed right-side Chat panel. It should be
   an EMBEDDED side panel inside the Kanban area (covers only the Kanban tab, Chat stays visible).
3. **Issue jump link**: the detail panel should have a 'view issue on GitHub' link
   (`https://github.com/{owner}/{repo}/issues/{n}`), and each sub-issue row should link to its issue.

## Task

1. **Backend** (`server/src/kanban/github-sync.ts` + `server/src/routes/kanban.ts`):
   - Add a `subIssues` array to `GithubProjectCard`: each entry `{ ref, title, status, number }` for the
     Spec's ticket sub-issues (title ref `Gx.Sy.Tz`, state → status, issue number).
   - `buildGithubProjectBoard` populates `subIssues` for each Spec card (from the repo's issues where
     the issue is a sub-issue of the Spec, matched by title ref prefix).
   - The `/api/kanban/github-project` response therefore carries each Spec card's subIssues.

2. **Frontend detail panel** (`web/src/components/KanbanTab.vue`):
   - Detail panel now shows: Spec md content (existing) + a **Sub-issues list** section (ref, title,
     status, per-sub-issue progress) + the existing Discussion (comments).
   - Each sub-issue row is clickable → opens that sub-issue's own detail (md + comments) using the same
     detail mechanism.
   - **Embedded panel**: change the detail from `position: fixed; inset: 0` overlay to an embedded side
     panel that covers only the Kanban tab area (e.g. `position: absolute` within the kanban tab
     container, width constrained, `z-index` below the fixed Chat panel), so the right-side Chat stays
     visible and usable.
   - Add a 'view issue on GitHub' link (owner/repo/issues/N) in the detail header, and link each
     sub-issue row to its GitHub issue.
   - **Comment input**: below the Discussion (comments) section, add a textarea + 'Post comment' button
     that POSTs to the new backend comment endpoint (createIssueComment) and then refreshes the comment
     list to show the newly posted comment.

3. **Backend comment endpoint** (`server/src/routes/kanban.ts`):
   - `POST /api/kanban/github-issue-comments` — body `{ repo, issueNumber, body }`, uses the employee's
     token + GitHubApi.createIssueComment. Returns the created comment. (Frontend posts here.)

4. **Tests**:
   - Server (`server/test/kanban-github-sync.test.ts` + `kanban-routes.test.ts`): assert the
     github-project response carries subIssues per Spec card (ref/title/status/number); assert the
     POST comment endpoint calls createIssueComment and returns the comment.
   - Web (`web/src/__tests__/kanban-tab.spec.ts`): assert clicking a Spec card opens a panel showing the
     sub-issues list; clicking a sub-issue opens its detail; the panel does not cover the full screen
     (embedded); a GitHub issue link is present; the comment input POSTs and shows the new comment.
   - Server + web tests green, typecheck/vue-tsc clean.
