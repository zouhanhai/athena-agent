## Context

S5 T2 built the md→GitHub projection. It currently adds **both** the Spec main issue AND every ticket
sub-issue to the Project board (`addIssueToProject` for each). The user's design decision (2026-08-13):
the **board should show only Spec cards** — tickets live as sub-issues under the Spec (click the Spec to
see them, with GitHub's native sub-task progress bar X/N). Two board levels (Spec + Ticket cards) is
cluttered; one Spec card per Spec is the right view. The Spec card's Status column reflects the **md
Spec status**, not a per-ticket aggregate.

## Task

1. **T2 change** (`server/src/kanban/github-sync.ts`):
   - In `createSpecIssue`, REMOVE the `addIssueToProject(project.id, ticketIssue.node_id)` for each
     ticket (currently line ~263). Keep adding only the Spec main issue to the Project.
   - Tickets are still created as sub-issues of the Spec (so GitHub shows the native sub-task progress)
     and still get milestone/label, but they are NOT individual Project cards.
   - Spec card Status column = the md Spec status mapped to a board column (extend `status-map.ts`:
     Spec statuses `backlog/active/done` → board `Backlog/In Progress/Done`).

2. **Frontend T4 sync** (`web/src/components/KanbanTab.vue` + `server/src/routes/kanban.ts`):
   - The `/api/kanban/github-project` response should carry only Spec-level cards (one per Spec), each
     with its sub-task progress (done/total from the sub-issues).
   - **Segmented progress bar** on each Spec card: N blocks = N sub-issues; each done sub-issue fills
     one block (like ABAPlorer's `4 / 5 · 80%` — number, segmented bar, percent). Show `done / total`
     and `percent`.
   - Card header shows the repo + Spec ref (like ABAPlorer's `owner/repo #id`).
   - The Workbench GitHub Project view renders only Spec cards, not ticket cards.

3. **Tests**:
   - Server (`server/test/kanban-github-sync.test.ts`): assert `createSpecIssue` adds ONLY the Spec to
     the Project (tickets are sub-issues, not board cards); spec status → column mapping.
   - Web (`web/src/__tests__/kanban-tab.spec.ts`): assert the GitHub Project view renders Spec cards
     with a segmented progress bar (done/total + percent), not ticket cards.
   - Server + web tests green, typecheck/vue-tsc clean.

## Acceptance

- Each Spec card has a segmented progress bar (N blocks = N sub-issues, done fills blocks) + done/total + percent.
- Spec card status = md Spec status.
- Workbench GitHub view shows Spec cards + segmented progress.
- Tests green, typecheck/vue-tsc clean, live-verified on 6900XT.
