## Context

The md→GitHub sync is currently manual (`server/scripts/sync-github.ts sync <specRef>`). When a worker
marks a ticket done, the GitHub board Status column stays stale until someone runs the sync manually
(observed 2026-08-13: T9 was done in md but still In Progress on GitHub until manually synced). The S4
plugin already hooks `session.idle` to commit the kanban index on done — extend it to ALSO run the
md→GitHub sync for the ticket's parent Spec, so the board stays in sync automatically.

## Task

1. **Plugin auto-sync** (`opencode-plugin/src/done-commit.ts` + `athena-worker.ts`):
   - In the `session.idle` done handler (where the index done commit happens), after the commit, ALSO
     run the md→GitHub sync for the ticket's parent Spec: derive `specRef` from the ticket ref
     (`G4.S5.T9` → `G4.S5`), then invoke the sync (the same `sync-github.ts sync <specRef>` logic, or a
     function from the athena core the plugin already imports).
   - The plugin needs a GITHUB_TOKEN / employee credential for the sync — resolve via the athena
     credential store (or a configured token / env).
   - Best-effort: a sync failure is logged but does NOT block or roll back the index done commit.

2. **Tests**:
   - Plugin (`opencode-plugin/test/done-commit.test.ts`): mock the sync invocation; assert that when a
     ticket is done, the plugin triggers `sync <specRef>`; a sync failure still allows the index commit.
   - Plugin tests green, server tests green, typecheck clean.

## Acceptance

- Worker done → plugin auto-runs md→GitHub sync for the parent Spec.
- GitHub board Status column updates automatically on done.
- Sync failure is best-effort (doesn't block done flow).
- Tests green, typecheck clean, live-verified on 6900XT.
