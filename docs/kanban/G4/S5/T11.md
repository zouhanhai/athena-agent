## Context

Bug (2026-08-13): `GET /api/kanban/github-project?repo=OWNER/REPO` resolves the Project by guessing its
title — `getProjectByTitle(credential, owner, "OWNER/REPO")` then fallback `(credential, owner, "repo")`.
This works only when the Project's title equals the repo name. `CALEO-Consulting/caleo.int.abaplorer`
returns 404 because its linked Project is titled **"Abaplorer Project"** (≠ repo name), even though
`organization(CALEO-Consulting){ projectsV2 }` contains it and the repo IS linked (verified via
`repository(owner,name){ projectsV2 }` → returns "Abaplorer Project").

GitHub exposes the correct link: `repository(owner,name){ projectsV2 { nodes { id title } } }` returns the
projects linked to that repo. Use that instead of title-guessing.

## Task

1. **New GitHubApi method** (`server/src/github/client.ts` + `graphql.ts`):
   - Add `getRepoProjects(credential, owner, repo): Promise<GithubProject[]>` that runs
     `query { repository(owner:$owner, name:$name){ projectsV2(first:100){ nodes{ id title number url } } } }`
     and returns the projects (handle "could not resolve" → empty array).

2. **Endpoint fix** (`server/src/routes/kanban.ts` GET /api/kanban/github-project):
   - Replace the title-guessing (getProjectByTitle owner/repo + repo) with:
     `const projects = await github.getRepoProjects(credential, owner, repo); const project = projects[0] ?? null;`
   - If no project, return 404 'no linked GitHub Project' (unchanged).
   - This makes any repo-linked project resolvable regardless of its title.

3. **Tests**:
   - Server (`server/test/kanban-routes.test.ts`): mock `getRepoProjects`; assert the endpoint returns a
     project whose title differs from the repo name (e.g. 'Abaplorer Project' for
     caleo.int.abaplorer); 404 when the repo has no linked projects.
   - Server tests green, typecheck clean.
