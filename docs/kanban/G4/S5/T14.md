## Context

The OpenCode worker plugin's auto-sync (T10) runs `createSpecIssue` when a worker marks a ticket done
(session.idle). But the GitHub board is MISSING G4.S5.T11/T12/T13 issues (only #1-#11 exist; T10 has #11).
Root cause: `opencode serve` is started WITHOUT loading `.env.local` (start-all.sh line ~113 has no env
load), so the plugin's `resolveGithubCredential` can't reach the Postgres employee store (no DATABASE_URL)
or GITHUB_TOKEN → the sync fails silently → new tickets never get a GitHub issue. Fix: load .env.local
before launching opencode serve, then create the missing issues.

## Task

1. **start-all.sh** (`scripts/start-all.sh`, OpenCode serve block):
   - Before `opencode serve`, load the athena env like the backend block does: `set -a && . .env.local && set +a`
     (from `$HOME/athena-agent`), so DATABASE_URL / GITHUB_TOKEN / GITHUB_EMPLOYEE reach the serve process
     and the plugin can resolve a GitHub credential.

2. **Create missing issues**: after the env fix + a serve restart, run
   `cd server && GITHUB_TOKEN=$(...) npx tsx scripts/sync-github.ts create G4.S5 --owner zouhanhai --repo athena-agent`
   (or `sync`) so G4.S5.T11/T12/T13 get their GitHub issues (idempotent createSpecIssue).

3. **Create-on-decompose (2026-08-13 user preference)**: the Eng Director should run
   `sync-github create|sync <specRef>` right after decomposing new tickets into a Spec, so ALL tickets
   (including backlog) get their GitHub issue immediately — the GitHub board reflects the full kanban from
   the start, not only when a ticket reaches done. `createSpecIssue` is already idempotent; this is a
   WORKFLOW trigger, not new code. Document it in the S5 spec / Eng-Director workflow.

4. **Tests**: no code unit test for start-all (shell), but verify by restarting serve and confirming a
   subsequent worker-done auto-sync works (or by checking the serve env has DATABASE_URL). Server + plugin
   tests green, typecheck clean.
