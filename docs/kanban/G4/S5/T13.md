## Context

The web Local kanban reads REMOTE GitHub md (readRemoteIndex/scanRemoteBoard). The Progress Log is written
LOCALLY on the worker machine and NOT committed to GitHub, so the remote md only has the claim-time row →
`isStalled` (based on the remote md's last Progress Log row) misjudges an actively-working ticket as
STALLED (observed 2026-08-13: T12). This misleads web users. **Decision: remove the stalled indicator from
the web Local kanban.** The stalled pattern is still valuable for the G7 local desktop app (which reads
local md with the real Progress Log); G7 will restore it. Keep the shared logic available for G7.

## Task

1. **Remove stalled rendering** (`web/src/components/KanbanTab.vue`):
   - Remove the `isStalled(...)` calls and the STALLED badge markup (`.kanban-card-stalled`) from the
     Local kanban card.
   - Keep `updatedAgoText` / "updated Xs ago" (still useful context), but do NOT derive a stalled flag
     from it in the web tier.
   - Remove the `.kanban-card-stalled` and `.kanban-card-updated-stalled` CSS (or keep the updated-stalled
     styling if trivial, but no badge).

2. **Preserve logic for G7** (`web/src/kanban/progress.ts`):
   - Keep `isStalled` + `DEFAULT_STALL_MS` exported in `progress.ts` (so G7 app version can reuse it), but
     it is no longer imported/used by KanbanTab.vue. Add a comment: "app-tier only (G7 local desktop app);
     the web tier reads remote GitHub md which lacks the local Progress Log, so stalled is not shown there."

3. **Tests**:
   - Remove/update the stalled assertions in `web/src/__tests__/kanban-tab.spec.ts` (the "flags an
     in_progress card as stalled" tests → now assert no stalled badge is rendered).
   - Keep `isStalled` unit tests in `kanban-progress.spec.ts` (the logic stays for G7).
   - Web tests green + vue-tsc clean.
