## Context

ED/PM build Goal/Spec/Ticket md files via planning (to-spec/to-tickets); every creation is committed.
Currently the md→GitHub sync is manual (`sync-github create/sync`) or auto on worker-done (T10) — so a
newly decomposed ticket only gets its GitHub Issue when someone remembers to sync or a worker claims it.
The user (2026-08-13) wants: **committing new board files auto-syncs GitHub** — so every Goal/Spec/Ticket
gets its Issue immediately on commit, and the GitHub board reflects the full kanban (incl. backlog) from
the start. A git hook is the chosen trigger (no always-on watchdog; works for every machine that installs it).

## Task

1. **Git hook** (post-commit or pre-push — pick post-commit as the natural "submit-and-sync" point):
   - Detect the commit added/modified new `docs/kanban/**/Goal.md`, `docs/kanban/**/Spec.md`, or
     `docs/kanban/**/T*.md` files (compare against the previous ref, e.g. `HEAD~1`).
   - For each affected specRef (from the new Spec.md / T*.md paths), run
     `cd server && npx tsx scripts/sync-github.ts create <specRef> --owner ... --repo ...`
     (or a full sync). For a new Goal (no spec yet), sync each spec under it after they're created.
   - Best-effort: log on failure, never block the commit/push (so a GitHub hiccup doesn't break dev).

2. **Distribution**: an install script (e.g. `scripts/install-kanban-hook.sh`) that:
   - sets `git config core.hooksPath` to a repo-tracked `hooks/` dir (so hooks live in the repo and every
     clone can use them), OR copies the hook into `~/.git/hooks/`; add to new-machine setup docs.
   - Document in the athena-agent-ops skill + setup.

3. **Tests**:
   - Shell-level test: a script/test that stages a new T*.md, commits, and asserts sync-github was invoked
     (e.g. dry-run/mock). Server + plugin tests green, typecheck clean.
   - Confirm no regression with the worker-done auto-sync (T10).
