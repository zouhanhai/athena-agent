## Context

The Workbench GitHub Project view marks a card as a "Spec card" (orange accent + segmented sub-task
progress bar) ONLY when its ref matches `Gx.Sy` (athena's Spec naming). `isSpecCard` =
`/^G\d+\.S\d+$/.test(card.ref)`. For a repo like abaplorer whose parent issues have plain titles (e.g.
#201 "ABAP Object Import" with 9 sub-issues #202-#210), the card shows NO progress and NO orange accent —
even though the issue has sub-issues. The user (2026-08-14) wants it universal: **any card whose issue has
sub-issues shows sub-task progress**, and a parent-of-sub-issues issue gets the Spec-card orange accent.

## Task

1. **Backend** (`server/src/kanban/github-sync.ts` `buildGithubProjectBoard`):
   - Currently `subTaskProgress(ref, issues)` + `subIssuesForSpec(ref, issues)` derive sub-issues by
     matching issue titles against the Gx.Sy ref. Generalize: a card's `progress` + `subIssues` should be
     populated when its issue is a PARENT of sub-issues (GitHub `sub_issues` relationship), regardless of
     naming. Use the issue's actual sub-issue list (from the board items / issue data) rather than
     title-matching.
   - Keep the existing Gx.Sy path working (it can still enrich the progress for athena specs).

2. **Frontend** (`web/src/components/KanbanTab.vue`):
   - `isSpecCard` should treat a card as a "Spec card" (orange + progress) when it HAS sub-issues
     (`card.progress.total > 0` or `card.subIssues.length > 0`), not only when `Gx.Sy`. Sub-issue cards
     (which have no sub-issues themselves) stay plain white.
   - Ensure the segmented progress bar renders for these cards.
   - **Status badge colors**: give `.kanban-project-card-status` (and `.kanban-detail-status`) the same
     per-status color classes as the Local kanban status badges
     (`.kanban-card-status-in_progress` yellow, `-done` green, `-backlog` gray, `-in_review`,
     `-approved`, `-rejected`, `-canceled`), so GitHub-view status pills are colored, matching the board.

3. **Tests**:
   - Server (`server/test/kanban-github-sync.test.ts`): a card whose issue has sub-issues (non-Gx.Sy) gets
     progress + subIssues populated.
   - Web (`web/src/__tests__/kanban-tab.spec.ts`): `isSpecCard` true for a card with sub-issues; a plain
     issue (no sub-issues) stays white; Gx.Sy spec still orange.
   - Server + web tests green, typecheck/vue-tsc clean.
