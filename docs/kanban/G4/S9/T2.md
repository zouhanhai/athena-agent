## Context

G4.S9 spec section 2: per-community LLM summaries power the global-QA path (T3).
T1 provides memberships; this ticket persists community nodes, generates summaries,
and defines the refresh policy so re-runs don't burn tokens on unchanged communities.

## Task

1. Community nodes + membership edges (upsert per T1 output).
2. Summarization pass:
   - Gather member entities + intra-community relations.
   - One LLM call (reuse the extraction-class direct-OpenRouter caller + reasoning
     off pattern from the refine toolchain — same provider path).
   - Output JSON: { summary, theme } persisted on the node.
3. Refresh policy: compare membership sets (hash of sorted member ids); re-summarize
   only changed; delete communities with zero members.
4. Hook decision: run after ingest/delete cycles (post-finalize in tasks.ts is the
   natural place) or expose an internal endpoint/trigger; document the choice; keep
   it non-blocking.
