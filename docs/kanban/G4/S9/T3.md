## Context

G4.S9 spec sections 3+4. With communities (T1) and summaries (T2) in place, this
ticket builds the global query path and the CO_OCCURS weak edges that mitigate
sparse-relation half-orphans. The existing local retrieval (vector+BM25+graph+rerank)
stays untouched as the default; global becomes an explicit mode.

## Task

1. Index community summaries: embed like chunks (OpenRouter embedder) + BM25 tokenize;
   store as a CommunityText / reuse Chunk with a marker; include in the fusion pool.
2. Global retrieval:
   - parse scope from the same query route (search_knowledge / api/kb/search);
   - top summaries → community ids → member entities → chunks (MENTIONED_IN);
   - fuse + rerank with existing machinery; answer via the agent as today.
3. CO_OCCURS edges in ingest/overwrite:
   - after mentionPairs (which already scans chunk text for entity names), also pair
     entities within each chunk; MERGE CO_OCCURS with weight; skip pairs that
     already have RELATION.
   - include CO_OCCURS in community detection input (T1 hook) and graph expansion.
4. Regression: default path behavior unchanged; suite green.
