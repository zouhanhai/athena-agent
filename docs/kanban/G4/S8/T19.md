## Context (2026-08-22, after three rounds of Mallorca/Lüsen re-upload debugging)

The pipeline has shown a repeating failure class: the LLM's relation endpoints
drift from the entity names it emits ("Hotel Palma Bellver *Afflicted* by Melia" /
"Hotel Palma *Belvedere*" / "München" vs "ZOB München"). T16's cross-field validator
rejects those, and after two validation-repair retries the whole document falls back
to the mechanical path — topic=unclassified, 0 entities, 0 relations, chunks from
heading splits. Multiple provider-sensitive attempts showed the drift is a coin toss
per run. A fuzzy matcher (already merged) helps but cannot rescue hallucinated tokens
("Belly" for "Affiliated"). The user decision (2026-08-22): every document gets ONE
mandatory independent audit session — cheap because reasoning is OFF and the payload
is entities+relations only. Audit is also the last-resort rescue before mechanical
fallback, so name drift can never nuke a document again.

## Design

### 1. Audit session (core deliverable)

- Reuse/extend the scaffolding already in `refine-document.ts` (commit 124b73c):
  `AUDIT_ENTITIES_PROMPT`, `buildAuditPrompt`, `runEntityAudit`, `AUDIT_ENTITIES_SCHEMA`.
  Make it correct, typed, and testable (injectable caller).
- **Audit input MUST include the ORIGINAL markdown context, not just the
  entity/relation lists** — the auditor has to see what each entity actually
  looks like IN the text to judge which name is canonical ("Belly" vs
  "Affiliated", "CALEO" vs "GALILEO"). Implement **occurrence-anchored
  context** (cheap + precise):
  - For EACH entity name (and alias forms), locate it in the markdown (exact,
    then case-insensitive, then fuzzy — reuse `headingPathForQuote` /
    `normalizeWs` helpers); take the ±200 chars around the best hit.
  - Also locate each relation endpoint's best hit.
  - Feed the audit prompt:
    `DOCUMENT EXCERPTS (around each entity/relation occurrence):`
    followed by the anchored snippets, then the CURRENT ENTITIES / RELATIONS
    lists. Do NOT dump the whole document (bounded tokens; large docs stay cheap).
  - Fallback: when an entity has NO hit anywhere in the markdown (source image
    text / OCR gap), note it explicitly in the prompt as "NO OCCURRENCE FOUND
    — decide from neighbouring entities/relations only".
- Wire into `runRefinePass`:
  - Main-pass validate-clean branch: run audit over the delta; adopt ONLY when the
    audited delta passes `validateRefineDelta`; otherwise keep the pre-audit delta
    and log.
  - Validation-exhausted branch: before `throw`, run audit once as rescue; if the
    audited delta passes validation, return it (log `audit pass rescued`); else throw.
- Ensure `RefinedDocumentDelta` passed to audit has the same shape the validator expects.

### 2. Graph + persisted output use the audited set

- `storeRefinementOutput`, the Neo4j `overwrite`/`ingest`, and `quality.json` must
  receive the FINAL (audited) entities/relations — trace the return path of
  `runRefinePass` and make sure the audited delta flows into the ref.

### 3. Full pipeline review (second deliverable)

Walk the chain with the fixtures / curl and fix REAL bugs found, at minimum investigate:
- re-upload after delete runs full pipeline (dedup purge keys — see d19b0b4 + 964d17d context; verify a fresh delete→upload passes)
- server restart loses NEO4J_* env (the documented start command in bash_history; the athena server must either shed light the NEO4J_PASSWORD-absent case gracefully or start-all.sh must export it — the production server was started OUTSIDE that script and silently ran without NEO4J: neo4j stage auto-done, graph empty)
- Document.md_ref pointing at the wiki-edit scratch dir after a wiki-edit overwrite (fix was in 99fb1f — verify/keep)
- stale frontmatter review_count when quality.json has no issues (fix in 99fb1f — verify/keep)
- review-state kinds (info vs action) — verify the UI groups behave (refinement notes vs needs-confirmation)
- the `k` refine guarantee: every refined doc has exactly one h1, a real type, a real topic

End state: delete→upload→edit→save→resolve loops clean in ONE pass on 6900XT, Neo4j has
real Document/Chunk/Entity/Relation rows, wiki pages carry review_state correctly,
web shows pending-review only when there are action-kind unresolved issues.
