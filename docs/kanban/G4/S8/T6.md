## Confirmed defects (from full review of T2 commit b0317ac, 2026-08-20; P0 live-verified on 6900XT)

### P0 — response_format is overwritten by the TypeBox schema on EVERY production call (100% 400 → silent full fallback)

`server/src/agents/llm-direct.ts:123`:
```ts
if (params.schema !== undefined) body.response_format = { type: "json_object", ...(params.schema as object) };
```
All three call sites pass a TypeBox `Type.Object(...)` schema (`HEADER_LEVELS_SCHEMA`,
`REFINED_DOCUMENT_DELTA_SCHEMA`, `GLOBAL_MERGE_SCHEMA`), which always contains `type: "object"`.
The spread therefore produces `response_format: { type: "object", required, properties }`.

**Live test on 6900XT (2026-08-20):**
- `{"type":"json_object"}` → 200 OK
- `{type:"object", required, properties}` (production shape) → **HTTP 400** `invalid_parameter_error: 'response_format.type' Invalid value: 'object'`
- `{type:"json_schema", json_schema:{name, schema}}` → 200 OK

**Consequence**: every refinement LLM call 400s, retains, and the caller's catch falls back to raw
docling markdown — refinement is silently OFF in production. Unit tests missed it because their fake
fetch stubs don't pass a schema.

**Fix**: build a correct OpenRouter response_format for schema'd calls:
```ts
body.response_format = {
  type: "json_schema",
  json_schema: { name: "refinement_result", strict: true, schema: params.schema },
};
```
or (simpler, matches current extractors) keep `{type:"json_object"}` and put the JSON schema only in
the system prompt. Either is acceptable — must be deterministic JSON output with no tool-call fiction.
Add a unit test: pass a TypeBox schema → assert the serialized body `response_format.type` is
`json_schema` (or `json_object`) — never `object`.

### P1 — non-retryable 4xx are retried (401 key-error burns 4 attempts)

Non-5xx/429 branches THROW an OpenRouterError, but the outer catch still honors
`if (attempt < retries) { sleep; continue; }` — so 400/401/403/404 are retried 3x with backoff.
401 (wrong/expired key) will never succeed — don't retry.

Fix: in the catch, skip retry for 4xx errors; only network/timeout/5xx/429/empty-content retry.
Add tests: 401 → exactly 1 attempt (no retry), throws; 400 → 1 attempt; 429 → retries.

### P1 — prompts still instruct 'call the emit_* tool' (no tools exist on direct HTTP)

- `server/src/agents/refine-document.ts` system prompts (`buildRefineSystemPrompt`, header
  re-level prompt, global merge prompt, retry nudge ~line 1042, file header comment ~line 16):
  still say "Call the emit_refined_document tool ... ONLY the emit_refined_document tool call".
  With direct HTTP there are no tools — the model must output raw JSON conforming to the
  requested shape. Leftovers confuse the model on retries and degrade quality.
- Update all prompts + comments to say: return a JSON object matching the contract (no tool call).
