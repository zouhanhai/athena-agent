## Context (2026-08-21, user requirement after G4.S8.T3/T4/T5)

T3/T4/T5 added SAP code intake (CDS DDL / ABAP / UI5) through a code channel. Today the stored
frontmatter is:

- `type: code` and `topic: cds` (or `abap`, `ui5`) — hard-coded literals in
  `server/src/kb/store/code.ts` (`renderCodeMarkdown` / `renderAbapMarkdown` / `renderUi5Markdown`
  and the three `frontmatter` objects in `storeCodeOutput` / `storeAbapOutput` / `storeUi5Output`).
- `code` is NOT one of the 13 DOC_TYPES, and `cds`/`abap`/`ui5` are not in the allowed
  TOPIC_TREE — so the wiki Topic view does not group code pages under a code/ folder, and the
  Type view has no canonical `code` category. Code pages also render like prose (only the generic
  hljs block highlight), with no visible system/package/transport lineage even though
  `CodeProvenance { system, devclass, transport }` IS already stored in frontmatter.

User requirement (verbatim intent): “llm_wiki 里也得有这三种 code 的显示优化, 不光是 md 文件;
然后 topic 里面添加一个 code 选项, 下面分为各个 sap 系统的名字, 由远程 agent 报告”.
So: (a) topic taxonomy gains `code/<system-name>` (system name reported by the remote agent at
intake — system already flows as `system` in the ingest payload / CodeProvenance);
(b) wiki shows code pages with an optimized display, not just an md wall.

## Design

### 1. taxonomy.ts (server/src/kb/taxonomy.ts)

- Add `"code"` to `DOC_TYPES` (13 → 14) with criteria line in TYPE_CRITERIA_PROMPT and
  counterexample (see acceptance): `- code: actual SAP source code / model definition (ABAP
  class/method, CDS view DDL, UI5 controller/view/fragment/Component). NOT a written description of
  code (-> spec/manual/concept); the source text itself is required, typically pulled from SAP via
  MCP or a repo.`
- Add `code: "code"` to `DOC_TYPE_DIRS`.
- Add to the end of TOPIC_TREE_PROMPT:
  `- code/<system-name> (SAP system the code was pulled from, e.g. code/prd, code/dev, code/qas; use code/unknown when the system is not reported)`
- Keep existing `sap/development/abap|cds|fiori` — those are for prose ABOUT development; the new
  `code/` branch is for actual source-code documents. State that distinction in the prompt.

### 2. store/code.ts (server/src/kb/store/code.ts)

- Change all three render functions AND the three store frontmatter objects so topic becomes
  `code/<system>`:
  - `topic: provenance?.system ? \`code/${sanitizeSlug(provenance.system)}\` : "code/unknown"`
  - sanitize: lowercase + replace non `[a-z0-9]` with `-` (reuse/extract a small helper; there is
    already a `normalizeTopic`-style regex in llmwiki — a local helper is fine, keep it simple).
- Keep `type: code`.
- Keep system/devclass/transport in frontmatter (already there).

### 3. Backend topic validation

- Confirm `isValidTopic` (server/src/kb/llmwiki.ts) already accepts `code/<system>` (regex allows
  slash paths) — if it does, no change; if it rejects something, adjust the regex/hyphen rules.
- `llmwiki` category check uses DOC_TYPES_JOINED — `code` will now be included automatically once
  DOC_TYPES gains it.

### 4. WikiView (web/src/views/WikiView.vue)

- When the currently rendered page (or the loaded frontmatter) has `type: code`, render a compact
  **code metadata panel** above the markdown body (only if frontmatter carries system/devclass/
  transport): e.g. `system: prd · devclass: ZGR_ANALYTICS · transport: XK9...` (TDesign Tag or a
  simple styled div). Keep it subtle, reuse the existing CSS vars (`--caleo-primary`,
  `--caleo-text-secondary`).
- How to get type/system/devclass/transport: the wiki tree nodes already carry `type`/`topic`;
  check how frontmatter reaches WikiView (likely via the page API — read the existing wiring and
  reuse it; if the page content API already returns frontmatter, parse it from the markdown head).
- Do NOT change the markdown rendering pipeline itself; hljs highlighting stays.

### 5. Tests

- taxonomy: `server/test/*taxonomy*` (or wherever taxonomy is tested) — assert `code` is a valid
  DocType and `code/prd` passes topic validation.
- store/code: the existing code-store tests assert topic `cds`/`abap`/`ui5` — update to
  `code/<system>` / `code/unknown`, add a system-sanitization case.
- web: run `npm run typecheck` (or the web build) — WikiView change must compile.
