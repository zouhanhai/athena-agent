## Context (2026-08-21, user report)

Two defects in the chat add-agent picker (web/src/components/GlobalChatPanel.vue):

1. **Duplicates**: agents already in the chat can be added again. `pickableAgents()`
   filters `availableAgents` by `agent.alias ∉ participants[].id`, but (a) the identity
   key is fragile (alias vs participant id — participants carry `agentId` too; any
   mismatch lets a joined agent reappear), and (b) `availableAgents` is loaded ONCE
   (`length === 0` guard) so the list is stale after adds/registrations.
2. **Athena perpetually offline**: the platform-seeded local Athena has no remote
   identity, so `registry.ts` derives `status: "unknown"` forever (L252: no tokenHash →
   unknown). The picker badge renders that as offline. The API genuinely does not model
   "this agent IS the platform" — the user is right.

## Design

### 1. Canonical dedupe key + refresh

- `addAgent` already stores `agentId` on the participant — filter with it:
  `const joinedIds = new Set(chat.participants.map(p => p.agentId ?? p.id))` and exclude
  `availableAgents.filter(a => !joinedIds.has(a.agent_id))` (keep an alias fallback for
  legacy participants lacking agentId).
- Load `availableAgents` on EVERY open of the picker (remove the `length === 0` guard;
  keep the error handling). Same treatment for the employee picker if identical.

### 2. Athena local status

- In the registry status derivation: when the agent is the platform-seeded local Athena
  (identify via the existing seed path — e.g. no api_url/token AND the seeded agent id),
  derive `status: "reachable"` OR introduce `AgentStatus = "local"`. Choose ONE, update
  the doc comment block (L18-24) and EVERY consumer mapping status → label/badge
  (GlobalChatPanel picker rows, SettingsView agent rows). The intent: the built-in agent
  is always available (it runs in-process), never "offline".
- Do NOT touch remote-agent reachability logic (`registered`/`reachable` via last_seen_at).

### 3. Tests

- Web: picker excludes a joined agent across reopen; list refetches on reopen (spy on
  listAgents call counts); badge shows online/local for the seeded agent.
- Server: registry derives the new status for the seeded local agent; remote agents
  unchanged.

- Manual matrix: add athena → picker no longer lists it; reopen picker → still excluded;
