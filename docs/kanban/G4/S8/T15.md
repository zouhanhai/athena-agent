## Context (2026-08-21, user requirement)

User requirement (verbatim intent): “不用定时清扫。把这个和 Athena 定时审核结合起来——athena
应该每个星期周末的时候开始一次知识数据库的审核，比如重新审批置信度、重新检查各个文件，
这个时候正好可以进行孤儿清理。” — i.e. NO standalone sweeper process: the orphan
refinement sweep becomes ONE STAGE of a scheduled weekly knowledge-base audit.

Building blocks that already exist:
- KB review service (`reviewAll`: re-topic / re-classify / deprecate / reinforce over all
  pages — G4.S3.T2) with confidence handling.
- T14's cascade primitives (graph subtree removal by documentId/md_ref) for repairing
  stale graph records.
- Refinement output root (`refinement/<stem>/markdown.md`) with Document.md_ref as the
  authoritative reference (T11/T14 conventions).

## Design

### 1. Scheduler (in-server, no external cron)

A small `KbAuditScheduler` wired in `src/index.ts`:

- Config via env: `KB_AUDIT_ENABLED` (default true), `KB_AUDIT_DAY` (default "sunday"),
  `KB_AUDIT_HOUR` (default 3, local time), `KB_ORPHAN_GRACE_HOURS` (default 48).
- Computes the next occurrence and sets a timeout; after each run re-computes the next.
  Persist `last_run_started_at` (Postgres table `kb_audit_runs` also serves report
  storage) so a restart mid-week never double-runs within the same configured window.
- Missed window while the server was down: run once at startup if the last successful run
  is older than the configured week.

### 2. Audit pipeline (three stages, one report)

```ts
interface KbAuditReport {
  startedAt: string; durationMs: number;
  review:    ReviewAllResult;          // stage 1 (existing service)
  fileCheck: { repaired: number; details: string[] };   // stage 2
  orphans:   { scannedDirs: number; removed: string[]; kept: string[] }; // stage 3
}
```

- **Stage 1 — review/confidence**: call the existing `reviewAll({})`.
- **Stage 2 — file/graph consistency**: diff WikiPage nodes vs disk *.md files
  (both directions). Stale graph subtree → remove via the T14 cascade primitives;
  missing graph record → report (do NOT auto-ingest).
- **Stage 3 — orphan refinement sweep**: list refinement output root dirs; delete a dir
  iff `age > KB_ORPHAN_GRACE_HOURS` AND no `Document.md_ref` references it AND no live
  wiki page shares its stem. Every removal is logged with its path.

### 3. Manual trigger + reports

- `POST /api/kb/audit` (admin permission): runs the same pipeline immediately (returns
  the report; concurrent invocations are rejected with 409 while one is running).
- `GET /api/kb/audit/reports?limit=` : recent persisted reports from `kb_audit_runs`.

### 4. Non-goals

- No LLM-driven content rewriting beyond what reviewAll already does.
- No deletion of QaPairs / semantic_mappings (terms) — user-maintained data.
- No standalone sweeper process — the weekly audit is the ONLY orphan sweep trigger
  besides the real-time T14 cascade.
