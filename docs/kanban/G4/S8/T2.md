## Observed (2026-08-20)

GR (Group-Reporing-SAP-Doc.pdf, 2.4MB / 3364 headers) stuck at `refining p=35` with **zero LLM
activity** (0 outbound 443 connections, 0.5% CPU, no new server log lines) for >10 min. Verified the
athena key is valid (auth OK, $1.6 remaining) — this is the **Pi ModelRuntime silent-hang** signature
documented in G4.S1 / ingest-refine-debugging: `completeSimple` has NO timeout; a dead/stalled provider
response leaves the await pending forever, the task stays "refining" forever, and there is no way to
recover it (in-memory task queue) short of restarting the server (which loses ALL task state).

## Root cause: Pi is overkill and dangerous for these 3 tasks

**All three refinement LLM calls are single-shot constrained-output calls — there is NO agent loop:**

| Call | Function | Pi usage | Output |
|---|---|---|---|
| stage-1 header re-level | `judgeHeaderLevelsLLM` (refine-document.ts:912) | `completeSimple` ×1/batch | `{"levels": {idx: level}}` JSON |
| stage-2 per-section | `runRefinePass` (refine-document.ts:1002) | `completeSimple` ×1/attempt + 3 retries loop (own) | `emit_refined_document` tool JSON (delta contract) |
| global merge | `runGlobalMerge` (refine-document.ts:~1040) | `completeSimple` ×1 + fallback | `merge` JSON |

Pi adds: no timeout, no retry (except the hand-rolled loop in runRefinePass), a provider catalog
(`Provider is not configured:` for anything new), and thinkingLevel `max` by default — 5042 reasoning
tokens per stage-1 batch (54s, $0.0034) when the task is a deterministic classification.

## Measurement (same 40-header batch, real GR data)

| model+config | time | reasoning tokens | cost |
|---|---|---|---|
| deepseek-v4-flash-latest + `reasoning:effort none` | **2.4s** | 0 | **$0.000085** |
| qwen/Qwen3.7-flash + `reasoning:effort none` | 2.3s | 0 | $0.000066 |
| qwen3.7-flash default | 26.4s | 11348 | $0.000599 |
| deepseek-v4-flash-latest (Pi `thinkingLevel max`) | 53.9s | 5042 | $0.00336 |

Conclusions:
1. **These 3 tasks need NO reasoning** — effort none gives identical JSON in ~2.4s (22x faster, 40x cheaper).
2. **deepseek-v4-flash-latest is the primary** (maxTokens 65536, output $0.28/M, 1.31M context); qwen (maxTokens 8192, output $0.60/M) only marginally cheaper on tiny outputs and 8x lower ceiling — fallback only.
3. `reasoning: {effort: "none"}` works on BOTH deepseek and qwen via OpenRouter (qwen's `enable_thinking: false` extra_body is silently IGNORED — must use `reasoning.effort`).

## Design

Replace the three `modelRuntime.completeSimple(...)` call sites with a tiny direct HTTP helper:

```
server/src/agents/llm-direct.ts   (new)
  callOpenRouter(params: {model, systemPrompt, userContent, schema?}): Promise<{text, usage}>
    - reads key: env ATHENA_OPENAI_API_KEY ?? ~/.pi/agent/auth.json → athena.key
    - model: env ATHENA_REFINE_MODEL ?? "~deepseek/deepseek-v4-flash-latest"
    - body: {model, messages, response_format: {type: "json_object"}}, max_tokens: 65536
    - ALWAYS: reasoning: {effort: "none"}
    - timeout: 120s via AbortController; retry 3x with backoff on network/timeout/5xx
    - returns parsed JSON content (parse `content`; if empty and `reasoning` present,
      treat as failure and retry with higher max_tokens)
    - NEVER emits `thinking` tokens: reasoning off
```

- **stage-1**: `judgeHeaderLevelsLLM` keeps its batch loop + `extractHeaderLevels`, but the inner
  `completeSimple` becomes `callOpenRouter` with the same HEADER_RELEVEL_SYSTEM_PROMPT +
  `buildHeaderJudgePrompt`. **Fallback per batch unchanged** (original level on parse failure).
- **stage-2**: `runRefinePass` keeps its 3-retry loop; body per attempt = `markdown` (+ re-prompt on retry);
  parse `emit_refined_document` args from the response (tool call or json_object — the current
  `extractRefinementDelta` already handles both). Schema-validate; on invalid → retry.
- **global merge**: `runGlobalMerge` same pattern; keep the `never worse: return merged` fallback.
- **Where the server loads it**: `server/src/kb/refiner.ts` `createAthenaRefiner` continues to return the
  same `Refiner` shape — internally it now builds the helper instead of `ModelRuntime.create()`.
  `createRefineDocumentTool` keeps its signature (tests inject `judgeHeaderLevelsImpl` etc.).
