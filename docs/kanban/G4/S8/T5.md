## Context (2026-08-20)

CALEO's consulting KB should also answer UI5-side questions: "which controller loads the Consolidation
grid", "what OData entity does this tile bind", "which CDS view backs this UI5 table". UI5 business
code is in the frontend repo (`webapp/`): controllers (.js/.ts/.xml views, `.model.json`),
`.manifest.json`, `Component.js`. This is the third (and last) code family in the code channel family
(T3 CDS, T4 ABAP, T5 UI5).

## Decision (from user discussion, 2026-08-20)

- **Business code only**: `webapp/` (or a UI5 project's app folder) — never `node_modules`, never
  generated build output. This is a hard scope boundary.
- Local parser: TS/JS AST (use the existing TS compiler API `typescript` — already in the repo? check
  `server` deps; else `acorn` for JS + a small XML parser for view.xml/manifest). No tree-sitter setup
  needed if TS compiler suffices.
- Same pipeline values: deterministic local chunking; LLM (T2 direct) only for enrichment; code stays
  verbatim; `path` = app/component/controller for context recovery.

## Design

### Intake

- `kind="ui5"` branch in the T3 code channel. Source shape options:
  - **Directory upload**: a small zip/tarball of `webapp/` (business code only) — the API extracts to a
    temp dir, walks `*.js`/`.ts`/`.xml`/`.json` (excluding any `node_modules`/`dist`/`test`), and
    submits each file as a unit with `filename` preserving the app path.
  - OR text payload with `@path: <app>/webapp/controller/...` header (same as T4 for single files).
- The ingest task queue + dedup sha256 + storage unchanged.

### Remote acquisition (repo side) — REQUIRED (2026-08-20 user note; same principle as T3/T4)

UI5 code lives in a frontend **git repo** (or SAP BTP app), not the user's disk — a remote agent
fetches and feeds athena:

**A. Pull side — repository agent (no SAP MCP needed for UI5):**
- The fetcher agent clones / checks out the UI5 app repo (e.g. `webapp/`), or uses a configured
  remote (GitHub/Bitbucket/ABAP Git Repo). It enumerates the business files
  (`webapp/controller/*.js|ts`, `webapp/view/*.xml`, `manifest.json`, `model/*.model.json`,
  `Component.js`), excluding `node_modules`/`dist` per the Decision.
- Output per file: `{ kind: "ui5", file, appName, component, sourceText, ref(commit/tag), ts }`.
  `ref` is the provenance: answers must know which commit/version the code reflects.

**B. Feed side — athena intake:**
- Same `POST /api/kb/ingest/remote` with `kind="ui5"` (or a `zip` of `webapp/` posted by the agent):
  machine-token auth, SHA-256 dedup + update-on-change, single task, per-file storage with
  `app/component/ref(commit)` provenance in frontmatter.
- Re-pull on tag/release = sync; unchanged files skipped.

### Parser (`server/src/kb/codeparse/ui5.ts` new)

- For controller/JS/TS files: use the AST to split:
  - per controller (the default) OR per top-level method if >400 lines
  - method boundary = function/class-method declaration (keyed by `getController()`/`sap.ui.define` name)
  - for linguistic safety (the model is not code-aware): only split at AST function boundaries,
    never mid-statement.
- For .view.xml: each view file = one chunk (XML is tree, do not split element boundaries — keep whole
  file; large controls may be one chunk with attr text; that's fine).
- manifest.json: one chunk (the whole config) — it's small & links the app metadata.

### Chunk shape (reuse)

```
{
  id: "cN",
  kind: "controller"|"view"|"xml"|"manifest"|"model",
  file: "webapp/controller/Report.controller.js",
  component: "com.caleo.consolidation",
  text: "...",             // verbatim
  path: "com.caleo.consolidation/Report.controller"
}
```

### Enrichment (T2 helper, required for value)

- One call per controller/view chunk:
- focus: what the controller does (user action mapping to business data), which OData service
  (`/odata/<service>`, `<entitySet>` in manifest/model binding), any CDS/UI ancestry ("/bupa/…") — the
  relations list gains `binds:` / `uses_entity:` roles linking UI5 chunk → CDS view / ABAP method
  (even if the target is unindexed yet, keep the name as a relation target for later resolution).

### Fixtures (`server/test/fixtures/ui5/`)

- minimal app: `manifest.json` + 2 controllers (one short, one >400 lines) + 1 view.xml + 1
  `.model.json` referencing `/reporting/CDS_VIEW`.
- Test: controller chunk count == 2 (large controller splits per method), view = 1, manifest = 1;
  node_modules file is ignored; path correct; enrichment only when flag on.
