## Context

T20 audit of the wiki-edit flow surfaced three director-reviewed findings left open
(referenced in T20's Gap Report, all CONFIDENCE high/med):

1. **Review gate never synced after edit** — runWikiSave (kb/tasks.ts:998-1148) does not
   restamp `review:` / `review_count:` on the wiki frontmatter (upload path does, tasks.ts)
   844-854). Production incident: Lüsen stuck at `review: required / count: 4` while quality
   issues were all resolved; also new review items from an edit are never surfaced.
2. **Post-edit quality.json unreachable** — wiki-edit output is stored under
   `wiki-edit-<stem>/` while Document.md_ref points at the original refinement dir
   (store/ingest.ts COALESCE protection). loadQuality (review-state.ts:148-170) checks
   md_ref dir then `<page-stem>` dir — never the wiki-edit dir, so the review UI serves
   the PRE-edit issue list forever.
3. **alignChunksToMarkdown keys by last heading segment only** — repeated tail titles
   (e.g. "Agenda" in Day 1/Day 2) collide; the wrong chunk can be refreshed
   (refine-output.ts alignChunksToMarkdown).
