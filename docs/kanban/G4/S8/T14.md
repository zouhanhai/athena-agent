## Context (2026-08-21, user-reported residue)

Deleting a wiki page leaves the ENTIRE knowledge-graph subtree behind. Root cause:
`ingest.deleteDocument` (server/src/kb/ingest.ts L598) only calls `llmwiki.deleteFile` +
`rebuildIndex` — the Neo4j cleanup code that exists (DETACH DELETE chunks/sections,
store/ingest.ts L340-406) is wired ONLY into the wiki-edit overwrite path (diff-refine
replacing chunks of the SAME documentId), never into the delete path.

Verified residue after deleting all content pages: 3 Documents, 8 WikiPage nodes pointing
at nonexistent files, 32 Chunks WITH embeddings (still pollute vector retrieval), 39
Entities, 41 RELATION edges, 92 MENTIONED_IN edges, 40 Sections.

Graph shape (verified): `Document -[:IS_DOCUMENT]-> WikiPage`, `Document -[:IS_DOCUMENT]-> Chunk`
(chunks carry `documentId` + `embedding`), `Entity -[:MENTIONED_IN]-> Chunk`,
`Chunk -[:HAS_SECTION]-> Section` (+ PART_OF/HAS_SUBSECTION between Sections),
`Entity -[:RELATION]-> Entity`. Document nodes carry `md_ref` pointing at the refinement
output `markdown.md`.

## Design

### 1. Graph cascade (new method on the Neo4j ingest service, e.g. `deleteDocumentCascade(documentIds)`)

For each resolved documentId:

```
1. MATCH (d:Document {id: $id}) — collect d.md_ref (for refinement cleanup) and
   detach-delete the subtree:
   MATCH (d:Document {id: $id}) MATCH (d)-[:IS_DOCUMENT*]-(x) WHERE x:Chunk OR x:Section
   DETACH DELETE x
   DETACH DELETE d
   (order matters: collect counts before deletion for the result shape)
2. MENTIONED_IN edges die with their Chunk nodes automatically.
3. Orphan entities: MATCH (e:Entity) WHERE NOT (e)-[:MENTIONED_IN]->() DETACH DELETE e
   — scoped AFTER all documentIds in this delete are processed (a batch delete can
   orphan an entity only at the end).
```

### 2. Document resolution (deleteDocument)

Resolve candidate documentIds for the deleted page via BOTH signals, unioned:

- `WikiPage {path: $path}` → `IS_DOCUMENT` → Document
- Fallback: `Document.md_ref ENDS WITH '/<stem>/'` (the refinement stem equals the wiki
  file stem by construction) — covers docs whose WikiPage node was never written.

Zero matches → clean no-op (page simply had no graph record).

### 3. Refinement directory cleanup

For each collected `md_ref`: `dirname(md_ref)` must resolve INSIDE the configured
refinement output root (guard against path traversal), then `fs.rm(dir, {recursive})`.
Collect removed dir paths into the result.

### 4. Result shape & error posture

```ts
{ ok, llmwiki: {path, error?},
  graph?: { documentsRemoved, chunksRemoved, sectionsRemoved,
            entitiesRemoved, entitiesRetained, refinementDirsRemoved, error? } }
```

The llmwiki file deletion ALWAYS completes first and `ok` reflects it (today's contract);
graph failures are reported in `graph.error` without blocking file deletion.

### 5. Out of scope

Weekly/orphan sweep lives in G4.S8.T15 (scheduled knowledge-base audit) — this ticket is
ONLY the real-time delete cascade.
