## Context (2026-08-22, post-T16 regression)

T16's header fix is partial: Lüsen now re-levels perfectly (1 × h1 + 4 × h2 + 1 × h3) but
the Mallorca fixture still produces 12 × h2 + 4 × h3 with no h1 — the contract requires
exactly one document title. Separately, the quality gate is a pure LLM judgment and is
provider-sensitive: the same Lüsen document was review_required (conf 0.8, ????? placeholder
caught) on Alibaba but auto_accept (conf 0.95, zero issues) on Baidu — while the
"Zustieg am ?????" defect remained objectively in the output. Objective defects must not
depend on LLM mood.

## Design

### 1. Header hierarchy completion

- Reproduce with the Mallorca fixture (cached docling input: 10,794 chars, 16 flat h2).
  Trace which path fires: model patches (emitted/applied/dropped counters exist since T16)
  vs the batched HEADER_RELEVEL fallback — and why neither yields the single h1.
- Likely directions: the h1-promotion patch is emitted but mis-targeted even with text
  anchoring (first-heading special case), or the model never promotes the title. Fix in
  whichever layer, keeping counters truthful.
- Post-condition assertion helper: `assertSingleH1(markdown)` used by tests AND by the
  fallback trigger condition.

### 2. Deterministic placeholder pre-check

- New pure function `scanObjectiveDefects(markdown): Array<{ quote, heading_path, pattern }>`
  — patterns: `\?{3,}`, `\bTODO\b`, `\bFIXME\b`, `\bXXX\b`, `lorem ipsum` (case-insensitive;
  list env-tunable via `REFINE_PLACEHOLDER_PATTERNS`).
- Runs after buildRefinedDocument, before the quality gate finalizes: each hit becomes a
  structured anchored issue (same shape as T16/T17 issues) and forces
  `action: review_required` + `complete: false` even when the LLM said auto_accept.
- Dedupe against LLM-raised issues by normalized-quote overlap so a defect the LLM already
  flagged is not listed twice.
- The wiki-edit path (diff-refine) runs the same scan over the rebuilt markdown.
