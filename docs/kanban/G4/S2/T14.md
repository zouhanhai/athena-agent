## Background

Current `Neo4jRetrievalService.search` fuses vector + BM25 (both Chunk hits) with RRF, but the graph
retriever (`Text2CypherRetriever`) returns **Entity** nodes (id = entity name), which can't RRF-fuse
with Chunk hits (different id space) — so graph results just get appended, wasting the graph's value.
Also there's no rerank: only statistical RRF fusion (docs/retrieval-analysis.md).

## Task

1. **Entity→Chunk link (ingest)**: in `store/ingest.ts`, link each Entity to the Chunk(s) whose text
   mentions the entity name or alias → `(:Entity)-[:MENTIONED_IN]->(:Chunk)`. Use Athena's entities +
   chunks. Idempotent MERGE.
2. **Graph returns chunks**: change `Text2CypherRetriever` to return Chunk hits (an Entity is matched,
   then its MENTIONED_IN chunks are returned with the entity context) instead of raw Entity nodes —
   so all three sources are Chunk hits.
3. **Graph in RRF**: `rrrFuse([vector, bm25, graph], topK)` so graph chunks participate in fusion
   ranking (not appended last).
4. **Cross-encoder rerank**: after fusion, rerank the fused top-k with a local cross-encoder
   (ONNX Runtime node — `onnxruntime-node`; model e.g. BAAI/bge-reranker-base or a lighter
   ms-marco-MiniLM). Inject as a `reranker` option (default off / fallback to RRF-only if unavailable).
   Query-first pair ordering. Only rerank the fused top-k (e.g. 20), never the whole corpus.
5. **TDD**: MENTIONED_IN created on ingest; graph retrieval returns chunks; RRF includes graph;
   reranker reorders when present. Real-doc verification.
6. Server tests green + typecheck clean.

## Notes

- Reranker is a small local model (0.1-1GB) — fits CPU or 6900XT GPU. Node runtime via ONNX.
- Reranking is optional: if the model/ONNX isn't available, fall back to RRF-only (no regression).

## Acceptance

- Graph chunks fuse in RRF; reranker reorders when configured; tests green.
