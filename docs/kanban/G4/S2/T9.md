## Observed (2026-08-10, T5 validation)

T5's `VectorRetriever.search` / `Neo4jRetrievalService.search` **hangs** (no response in 60-90s) when run
against the live neo4j-spike container. Repro:
- `svc.search("ZOB München")` timed out (>60s) via `defaultNeo4jRetrieval()`.
- `VectorRetriever.search` with a fake embedding also timed out (>60s) — so the hang is in the **Cypher
  vector search**, not the embedder.
- Embedding itself is fast (3.9s, 4096-dim).
- Retrieval API `/api/kb/search` returns only `llmwiki` results (the Neo4j search hangs → allSettled
  drops it), so the neo4j source never surfaces.

Neo4j now has 15 Chunks + 14 Entities (real Infos doc ingested via T4). T3's schema + index were
"live-verified" in the spike, so likely the **Cypher SEARCH/VECTOR INDEX clause** is wrong for the real
data shape (e.g. index name, property, or the `SEARCH … IN (VECTOR INDEX …)` syntax at runtime), causing
the driver call to block or error-retry.
