## Goal

Make the RAG (Neo4j chunks) and wiki (llm_wiki files) ONE fused whole, so an agent summarizing
search results can group wiki pages with their chunks (docs/ingest-retrieval-flow.md).

## Design (authoritative: docs/ingest-retrieval-flow.md → "RAG ↔ Wiki fusion graph model")

```
(:WikiPage {path: "wiki/internal/events/X.md", topic, title})
    │ IS_DOCUMENT
(:Document {id, title, topic, md_ref})
    │ HAS_SECTION
(:Section {title})   ← H1
    │ HAS_SUBSECTION
(:Section {title})   ← H2
    │ PART_OF
(:Chunk {id, text, embedding})
```

- `heading_path` (e.g. "A / B / C") split on `/` → Section chain (H1→H2→H3), Chunk PART_OF deepest.
- WikiPage node per llm_wiki page; Document -[:IS_DOCUMENT]-> WikiPage bridge.
- Chunk retrieval results carry `wikiPath` (the WikiPage path) + `sectionPath` (heading chain).
- Context enrichment: retrieving a chunk returns the same-section sibling chunks.

## Task

1. **Schema** (store/schema.ts): add `Section` + `WikiPage` labels; HAS_SECTION / HAS_SUBSECTION /
   PART_OF / IS_DOCUMENT relationship types; constraints/indexes.
2. **Ingest** (store/ingest.ts): parse each chunk's `heading_path` into a Section chain (split on
   `/`), create Section nodes + relationships, link Chunk→deepest Section, link Document→WikiPage
   (wiki path = the llm_wiki page path written for this doc). Idempotent (MERGE).
3. **Retrieval** (store/retrieval.ts): chunk Cypher joins to its Section chain + Document → WikiPage
   so each hit carries `wikiPath` + `sectionPath`. Context enrichment: also return same-section
   sibling chunks.
4. **API surface** (kb.ts / retrieval.ts): `KnowledgeSearchResult` gains optional `wikiPath` +
   `sectionPath` on neo4j hits.
5. **TDD**: ingest creates the full graph; retrieval returns wikiPath/sectionPath; same-section
   context enrichment returns siblings. Real doc (Infos) verification.
6. Server tests green + typecheck clean.

## Acceptance
