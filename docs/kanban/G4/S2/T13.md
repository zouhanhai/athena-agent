## Background

Athena is the single full-document LLM pass in the ingest pipeline. It already reads the whole text,
so emitting a concise document summary costs nothing extra (unlike a separate summary LLM call).
This summary feeds a hierarchical/content index for retrieval (docs/ingest-retrieval-flow.md):
a user can search summaries to locate the most relevant document before digging into its chunks.

## Task

1. **Contract** (refine-document.ts): `RefinedDocument` + `RefinementOutputRef` gain:
   - `summary` (string, file-level, ~2-3 sentences) AND
   - `sections: { title: string; summary: string }[]` (one summary per top-level H1 section).
   Update `REFINED_DOCUMENT_SCHEMA`, prompt, `normalizeRefinedDocument`.
2. **Neo4j** (store/ingest.ts): store `summary` on the `Document` node; store each section summary
   on the matching `Section` node (T11 already builds Section nodes from heading_path — match by
   title/H1 and set `s.summary`). This enables layered/hierarchical summary retrieval.
3. **llm_wiki** (ingest.ts / llmwiki): write `summary` to the wiki page frontmatter (e.g. `summary:`).
4. **Retrieval (optional, if easy)**: summary fulltext indexes so summary text is searchable for
   hierarchical-lookup (search file summary → locate doc, then section summary → locate section, then chunks).
5. **TDD**: refine emits file + per-section summaries; summary persisted to Document, Section nodes,
   and wiki frontmatter.
6. Server tests green + typecheck clean.
