## Context

GDD (git-driven development) is a **generic, agent-agnostic dev-flow protocol** that runs on the
**user's LOCAL machine** — the user's own plan agent (Eng Director) and code agent (Worker) operate on
`docs/kanban/*.md`, sync them to GitHub, and log Progress Log. **athena is only an OPTIONAL viewer**
(the Workbench reads GitHub Project boards). Therefore GDD must be **independently runnable on the
user's machine** — NOT coupled to the athena server, its employee store, or its github client.

Currently GDD lives inside the athena monorepo and its sync code imports athena's `employees`
(credential store) + `github/client`. This ticket extracts GDD into a self-contained `gdd/` package
that runs standalone on the user's machine (2026-08-14 decision). Must be done AFTER T1 (Kanban/Project
split) and T2 (spec state machine simplification).

## GDD vs athena boundary (2026-08-14)

- **GDD (move into a `gdd/` package, runs on the user's machine)** = sync + protocol + templates +
  hooks + plugins: `server/src/kanban/` (github-sync sync half, scan, schema, status-map, board,
  git-lock, github-feedback, planning, progress, protocol, lifecycle, roles, state-machine, frontmatter),
  `server/scripts/sync-github.ts`, `hooks/post-commit`, `scripts/install-kanban-hook.sh`,
  `opencode-plugin/`, `docs/kanban/templates/`.
- **athena (stays)** = the UI/read layer that reads GitHub directly: `web/src/` (Workbench
  Code/Issues/Project tabs + api/github.ts), `server/src/routes/kanban.ts` + `routes/github.ts`,
  `server/src/github/` (client), `server/src/employees/`.
- **Split shared modules into two files** so each side is clean. The only kanban module used by both is
  `github-sync.ts`: split it → the **sync half** (`createSpecIssue`, `syncSpecStatus`, `specIssueState`,
  ticketState, subTaskProgress used by sync) → GDD; the **read half** (`buildGithubProjectBoard` + the
  helpers the Project tab needs) → athena (keep in `server/src/kanban/` or a new `server/src/github/
  project-board.ts`). The local kanban index (kanban-index.json, write-index.ts, index-file) and the
  done-commit plugin were already removed in T4.
- **Credential (critical)**: because GDD runs on the user's own machine (NOT inside athena), it must
  resolve GitHub credentials itself, LOCAL-token-first: `gh auth token` (gh CLI / hosts.yml) →
  `GITHUB_TOKEN` env → athena employee store ONLY as optional fallback when running inside athena.
  Update `sync-github.ts` and `opencode-plugin/src/auto-sync.ts` resolvers accordingly. GDD must not
  hard-require athena's Postgres employee store.

## Task

1. **Create the `gdd/` package** (or a `packages/gdd/` workspace) that is self-contained: its own
   package.json/tsconfig, and its own credential resolution (gh CLI → GITHUB_TOKEN → optional athena
   employee store). It must run on a fresh machine without the athena server/DB.
2. **Move the GDD code** into `gdd/`: kanban protocol/sync modules, `sync-github.ts` CLI, hooks
   (`post-commit` + `install-kanban-hook.sh`), opencode plugins, and `docs/kanban/templates/` (copy
   into `gdd/templates/`). Update all imports/refs.
3. **Move the GDD docs** into `docs/gdd/`: `docs/git-kanban-design.md` → `docs/gdd/design.md` and
   `docs/git-driven-protocol-review.md` → `docs/gdd/protocol-review.md` (update refs). This is the
   source content T5's README/index will reference.
4. **Split `github-sync.ts`**:
   - GDD side: `createSpecIssue`, `syncSpecStatus`, `specIssueState`, `ticketState`, `subTaskProgress`
     (sync projection used by sync-github CLI + auto-sync plugin).
   - athena side: `buildGithubProjectBoard` + the helpers the Project tab needs (kept in athena, e.g.
     `server/src/github/project-board.ts` or `server/src/kanban/`). athena routes call the athena side.
   - Both sides build + their tests pass.
5. **Local-token-first credential**: implement a GDD credential resolver (`gh auth token` →
   `GITHUB_TOKEN` → optional athena employee store) in `gdd/`; update `sync-github.ts` +
   `opencode-plugin/src/auto-sync.ts` to use it. GDD runs standalone with just the user's gh token.
6. **De-couple from athena**: remove GDD's imports of `server/src/employees` + `server/src/github`
   where they are only for the sync path; inject/resolve locally instead. athena keeps its own github
   client for the read routes.
7. **Update refs**: README.md, AGENTS.md, kanban docs, sync-github docstrings, install script paths.
8. **Verify**: `gdd sync-github create <spec>` runs standalone on the user's machine (with only a gh
   token / GITHUB_TOKEN, no athena DB); server + web tests green on 6900XT.
