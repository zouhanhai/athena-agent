## Context

The Spec state machine (GDD §7, built in G4.S5.T7) has a `decomposed` intermediate state
(`backlog → decomposed → in_progress → done → in_review → approved/rejected`) that the user decided
(2026-08-14) is unnecessary. Specs should be **ticket-driven**:

- When the FIRST ticket of a spec is claimed (→ in_progress), the spec auto-advances
  `backlog → in_progress`. No manual `decomposed` step.
- When ALL tickets are done, the spec does **NOT** auto-advance to done — it stays `in_progress`
  awaiting **review** (the reviewer may decide to add new tickets, so done is not automatic). Done is
  reached only through review (manual Eng Director / Reviewer).

## Task

1. **Remove `decomposed`**:
   - `schema.ts`: drop `"decomposed"` from the spec status enum.
   - `state-machine.ts`: remove the `decomposed` node + its transitions; `backlog` may go to
     `in_progress` directly. Legacy `active` still maps to `in_progress`.
   - `status-map.ts`: remove `decomposed` → "In Progress" (keep `in_progress` → "In Progress").
   - `github-sync.ts`: the Spec Status field option descriptions; ensure no reference to decomposed.

2. **Add ticket-driven auto-advance**:
   - When a spec's first ticket transitions to `in_progress`, advance the spec `backlog → in_progress`.
     Where does this live? Prefer the plugin/lifecycle on claim (or a derived rule in sync). Keep it
     simple — an explicit "advance spec on first ticket claim" step in the claim flow.
   - Do NOT auto-advance spec → done when all tickets done (stays in_progress for review).

3. **Sync the spec MAIN ISSUE open/closed to spec status**:
   - In `createSpecIssue`, when updating the existing spec issue, also set its `state`:
     `done`/`approved` → `closed`; `backlog`/`in_progress`/`in_review`/`rejected` → `open`. Add a
     `specIssueState(specStatus)` helper (mirrors `ticketState`). This makes the Project Status column
     and the issue-list open/closed agree for the spec issue (previously spec main issue stayed open
     forever while its Status column showed Done).

3. **Docs**: update `docs/git-kanban-design.md` §7 Spec state machine (remove decomposed, document the
   ticket-driven rule); update `docs/kanban/G4/S5/T7.md` (the original spec-state ticket) or add a
   note; regenerate `docs/kanban/kanban-index.json`.

4. **Tests**: update spec-state-machine tests (remove decomposed cases), add cases for
   backlog→in_progress auto-advance on first ticket claim, and confirm no auto done. Server + web
   tests green, typecheck/vue-tsc clean.
