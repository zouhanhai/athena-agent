## Context

A minimal wiki edit (one word in an image description: GALILEO Office→CALEO Office)
currently re-triggers the full extraction: the wiki-edit refine re-emits ~13
entities from the whole document, the LLM fluctuates (drops the office entity,
labels CALEO as person), and the Neo4j overwrite — whose entity set is the
refine output — cleans the old entity's source/mention edges, leaving
GALILEO Office as an orphan while CALEO Office was never created. The root
cause: the wiki-edit prompt has NO awareness of the document's existing
entities, so every edit is a from-scratch re-extraction with an unstable
outcome each time.

## Task

1. Baseline input: edit path reads the document's current entities from the
   graph (wikiPath → Document → MENTIONED_IN entities) and injects them into
   the wiki-edit refine prompt as the KNOWN ENTITIES baseline (cap 100).
2. Contract: wiki-edit output becomes delta-identity vs baseline — renames,
   added, removed, changed_relations, unchanged (implicit keep). NOT the full
   list re-emission.
3. Overwrite: applies baseline+delta; unchanged entities keep all connections
   (source_docs, mentions, relations, type). Rename = update node name +
   keep connections; added = create; removed = only if also absent from new
   chunk text.
4. Link: still runs on the delta candidates (rename/add), so a rename
   re-links to the correct existing node before/alongside the stored write.
5. Regression: no-orphan test (the GALILEO Office scenario).
