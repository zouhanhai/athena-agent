## Context

2026-08-26 empirical evidence: the SAP "CDS Views for Finance" extract (6MB md, 14150 flat
docling headers) was re-leveled by hand against the official SAP Help Portal TOC (via the
`pagecontent` API → `fullToc`). Results:

- LLM/current path: 14150 headers, wildly wrong hierarchy (deep leaves at h2, millions of
  template-field pseudo-headers like Purpose/Prerequisites → 12000+ noise headers) and it
  produced unstable output across runs.
- TOC-driven rebuild (a simple deterministic script matching md headings to the TOC pre-order
  walk): 1927/1977 nodes matched, correct hierarchy D4→h1 … D8+→h5, 12035 template headers
  demoted to bold paragraphs. Chunks will now align to real CDS-view boundaries.

Lesson: **for documents that ship a real table of contents, the document's own hierarchy is
the ground truth; LLM re-grading is strictly worse and non-deterministic.** The refine pipeline
must prefer the document TOC when available and only fall back to LLM judgment when there is no
TOC.

## Task

1. **TOC detection adapter** — build one interface `HeaderGradingSource` with three providers:
   - `pdf-outline-avail` : docling already exposes document structure; check whether the PDF
     outline/bookmark layer is available (docling `DocumentInputData` or `result.document`
     revisions). When present, extract the heading tree.
   - `markdown-toc-preamble`: scan the refined markdown preamble for a TOC-shaped block
     (list of chapter titles with consistent levels/links, e.g. the `- [Title](...)` pattern at
     the top of SAP exports). Heuristic + configurable.
   - `external-toc`: an optional `toc` JSON/array passed into refine (e.g. fetched from SAP
     Help Portal API by the uploader, mirroring `sap-help-docs-bulk-download`).
2. **Deterministic grading** — when a provider returns a TOC tree, build the md heading
   assignments by matching md headings against the TOC pre-order (normalize page numbers,
   punctuation, code suffixes). Same algorithm used in the manual rebuild but in-repo.
3. **Fallback** — sections that match no TOC node keep a conservative default (or the existing
   LLM judge for that batch only), and the whole pipeline falls back to
   `judgeHeaderLevelsLLM` when NO TOC is present. Never block on TOC providers failing.
4. **Mode reporting** — refinement quality/report carries `headerMode: "toc" | "llm"` and, for
   toc mode, `tocMatched/N` counts.
5. **SAP convenience** — a small helper in the SAP skill (`sap-help-docs-bulk-download`) can
   fetch `fullToc` for a delivered doc; document how to wire it to upload as `external-toc`.

## Acceptance

See frontmatter `acceptance_criteria`. The bar: for a TOC-backed doc the pipeline itself
produces the clean hierarchy deterministically (no manual script); for TOC-less docs behavior
is unchanged.
