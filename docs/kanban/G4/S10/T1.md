## Context

See G4.S10 Spec Design 1-4. The engine will be used by both the upload and the
wiki-edit pipelines, so keep it channel-agnostic (candidates in, decisions out).
The existing refine output already carries name/type/description/occurrences;
the graph store already has vector+BM25 over entities. Link is the first stage
that CONSULTS the existing graph.

## Task

1. `linkCandidates({ candidates, existingGraphApi })`:
   - query existing via exact/alias/vector≥0.92/BM25 → per-candidate top-K.
   - deterministic merges; ambiguous → LLM prompt (bounded input, json_schema).
   - validate + return decisions.
2. Wire into ingest (upload defaultIngest refiner chain) BEFORE audit; wire the
   same call into runWikiSave delta path.
3. Atomic apply: merge aliases + source_docs + relations redirect + new edges,
   in one session/txn; global mutex on the write phase.
4. Retry/repair/degrade per acceptance.

## Acceptance

Per frontmatter.

## Notes

- Reuse the refinement LLM caller (reasoning off, json_schema) — no new provider.
- Deterministic tier must be unit-testable without LLM (inject fake).
- Evidence quotes come from the candidate's occurrences and the top-k match's
  matching chunk/entity — reuse existing retrieval (mentionPairs coverage).
