## Context

Empirical evidence from 2026-08-25 uploads (all on OpenRouter deepseek-v4-flash, two-stage
path in `server/src/agents/refine-document.ts`):

| Document | Size | Result |
|---|---|---|
| EPM Add-in Guide | 1.22M chars | two-stage OK — 2521 chunks / 108 ents / 98 rels |
| Group Reporting | 2.40M chars | FAILED — "assistant returned no structured output" after retries → mechanical fallback, 0 chunks, topic unclassified |

Probe results on the GR markdown (`splitByHeaders` / `splitByRefinedH1` / `enforceSectionSize`):

- 3346 header blocks (avg 690 chars body) fed to stage-1 judging
- RAW docling output has essentially ONE h1 → `splitByRefinedH1` yields a single 2.38M-char
  section → size cap cuts it into 3 parts (1.05M / 1.05M / 0.28M) mid-chapter
- The REAL run's section count is UNKNOWN — nothing is logged

Root problems identified (fix ALL):

- **P1 — all-or-nothing section loop**: in `refineLargeDocument`,
  `for (const section of sections) { refinements.push(await stages.refineSection(...)) }` has
  no try/catch. One persistently-failing section throws → whole document collapses to the
  mechanical fallback (0 chunks). This is what killed Group Reporting.
- **P2 — zero observability**: no logs anywhere in the large-doc chain (stage entry/exit,
  batch progress, section count/headings, per-section outcome, durations). Failures are
  unattributable after the fact.
- **P3 — silent batch swallowing**: `judgeHeaderLevelsLLM` catches per-batch errors with an
  empty catch and keeps original levels — partial releveling failure is invisible and degrades
  the downstream split.
- **P4 — section size at the degradation edge**: `SECTION_MAX_BYTES = 1MB` ≈ 260K tokens of
  input per refine call. Empirically deepseek-v4-flash starts returning empty/invalid
  structured output in this region (both GR parts at ~1.05M chars failed; every smaller
  document succeeded). Consider a lower default (512KB ≈ 130K tokens — still 10x the biggest
  healthy call) or adaptive sizing; must stay env-tunable.
- **P5 — degenerate split path**: when the document has fewer than 2 usable h1s (flat docling
  output), splitting relies purely on the size cap and cuts mid-chapter. Add an h2-based
  fallback boundary selection so parts stay semantically coherent even without h1 structure.

## Task

1. **P1**: wrap each `stages.refineSection` call in try/catch. On failure after the pass's own
   retries: keep the ORIGINAL section markdown, mark it degraded, continue. `globalMerge` gets
   the same treatment conceptually — if it fails, fall back to concatenating successful section
   documents rather than throwing. Surface `degradedSections: string[]` (heading paths) on the
   result and include it in the operator review message.
2. **P2**: add structured logs at each stage: `[refine-large] blocks=N`, `[refine-large]
   releveled ok/fail-batches=M`, `[refine-large] sections=N [headings…]`,
   `[refine-large] section i/N "<heading>" ok/degraded (Xs)`, `[refine-large] merge ok/degraded`.
3. **P3**: count batch failures in `judgeHeaderLevelsLLM`, return them (or attach to a result
   object), log the count, and include it in the refinement quality report.
4. **P4**: evaluate `SECTION_MAX_BYTES`: default 512KB (env-tunable via existing pattern),
   document the token math in a comment. If evidence favors keeping 1MB, justify in Notes.
5. **P5**: in the split path, if `splitByRefinedH1` produces a single oversized section, try
   splitting at the deepest consistent header level (h2 first) before falling back to raw size
   cuts.
6. Tests for isolation, reporting, batch counting, and the h2 fallback split. Then re-upload
   Group Reporting on 6900XT and record evidence.

## Notes

- Single-pass delta extraction empirically handles up to ~1.2M chars total (EPM); beyond that
  the two-stage path is mandatory — keep `isLargeMarkdown` threshold as is.
- Do NOT change the delta contract or the wiki-edit baseline flow (G4.S10.T4) — this ticket is
  only about the large-document path's resilience and observability.
- Cost note: a failing ~1MB section burns 4 calls × ~260K tokens before giving up; P1 turns
  that waste into one degraded section instead of a dead document.
