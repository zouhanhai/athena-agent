## Context (from the 2026-08-26 CDS Views incident)

The 6MB CDS Views export produced 14,150 flat/wrong headers from docling. Manual repair
(today, shipped as G4.S10.T6 TOC-first grading) fixed it deterministically when a real TOC
exists — but documents WITHOUT a usable TOC/bookmark layer still fall to the LLM path or
ship broken hierarchies into chunks/entities/graph. The missing piece is a HUMAN gate:
parsing is cheap to redo, but refinement/chunking/graph-ingest bake bad headers into
12K+ chunks — expensive to undo (see today's wiki-edit re-run).

Design agreed with the user:

```
upload → parsing → [pending_header_review ⏸] --approve--> refinement → ingesting
                          |
                          +--reject/skip --> existing behavior (auto-advance)
```

During the pause, the reviewer works in a CARD EDITOR (explicit user requirement:
"最好是可以移动的 / 卡片式"):

- Every heading = one CARD showing current level chip (#/##/###...), title, children count.
- Drag card up/down among siblings = reorder; drag left/right = promote/demote that
  subtree; drop ON another card = re-parent under it.
- Level +/- buttons and keyboard shortcuts as accessible alternatives to dragging.
- Everything edits a DRAFT (in-memory + persisted JSON), with a live preview of the
  resulting tree; nothing touches the md until Approve.

## Task

1. **Stage machine**: add `pending_header_review` between parsing and refinement; skip it
   entirely (config flag per project, default off→on later) for tiny docs (< N headers).
2. **Draft model + API**: GET the detected outline (merging docling sidecar + T6 TOC match
   info); PUT a draft of level/parent/reorder edits; POST approve (writes headers back +
   advances) / POST reject.
3. **Card editor UI**: virtualized list (must handle 2000+ cards smoothly); per-card level
   chip colored by depth; subtree collapse; search/filter jumps; "changes: N" badge +
   undo stack. Keep interactions keyboard-accessible.
4. **Athena assist**: button posts the current outline (+ small text samples per suspicious
   section) through the refinement judge path; suggestions come back as batch operations
   (demote-to-bold X, set-level Y, re-parent Z) shown as APPLY chips — never auto-applied.
5. **Template demotion bulk action**: editable word list (Purpose, Prerequisites,
   Related Information, ... defaulting to the SAP set we validated) → converts matching
   headers to bold paragraphs in the draft, preview before save.
6. **Safety**: refuse to send >48K chars to any LLM call (align with the 66489b8/c7642ce
   caps); sample sections client-side instead.

## Notes

- The md header rewrite MUST be idempotent and preserve all non-header content verbatim
  (no LLM rewriting of body text — today's rule-based approach only).
- Reuse the existing wiki-edit delta machinery for persisting corrected headers so
  downstream (chunks.json rebuild + Neo4j re-ingest) behaves exactly like a manual edit.
