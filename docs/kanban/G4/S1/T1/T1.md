# G4.S1.T1: refine_document Pi custom tool

## Task

Register the Athena document-refinement LLM pass as a Pi **custom tool** `refine_document` (per G4.S1 Spec).

## Steps

1. **Tool registration** — add `refine_document` to the athena agent's `customTools` (`ToolDefinition`):
   - params: `{ markdown: string }` (docling output), optional `{ topic_hint?: string }`.
   - `constrainedSampling` with the output JSON schema (see T2) so the result is schema-conformant.
   - `executionMode` sequential.
2. **Provider/model** — use `modelRuntime.getModel("athena", "~deepseek/deepseek-v4-flash-latest")`
   (dedicated `athena` OpenRouter provider = independent key for independent cache/cost).
3. **models.json** — add `athena` provider entry (same model set as `openrouter`) so getModel resolves.
4. **thinkingLevel high** — header semantic re-leveling needs higher reasoning.
5. The tool internally: reads full md → LLM pass → returns the output contract (T2). Big-output
   handling in T3.

## Deliverables

- `refine_document` Pi custom tool wired into the agent (server/src/agents).
- `athena` provider in models.json (6900XT + local).
- Tool returns the structured output contract.
