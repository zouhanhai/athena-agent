# G4.S1.T3: big-output handling + chunking

## Task

Handle large md output (per G4.S1 Spec: pi-docparser pattern + measured size budget).

## Big-output pattern (pi-docparser)

`refine_document` returns the **small metadata** (frontmatter, entities, keywords, quality, md ref) into
context; the **full re-leveled markdown + chunks** land on disk/storage for downstream to read by
reference — keeps large md OUT of subsequent LLM context.

## Chunking for large docs

Measured reference (2026-08-09): 827pg SAP doc = 2.17MB md (27,917 lines, 3,364 headers). That's
~55-65k tokens + output inflation → near/over 1M context. So **>=1-2MB md MUST chunk**:

1. Split by `##` headers into section blocks.
2. Refine each block independently (header re-level + local quality).
3. Merge blocks + one global type/topic/entity/keyword pass.

NOTE: chunked refinement loses cross-section entity/relation correlation — single-read is preferred for
sub-1MB docs; chunking is the fallback.

## Deliverables

- Big-output storage (full md + chunks to file/storage; metadata + refs returned).
- Chunking helper (split by headers, refine, merge).
- Size-based routing (sub-1MB single-read; >1MB chunk).
