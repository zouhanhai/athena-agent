# G4.S1.T6: refine_document structured-output fails on complex docs

## Observed (2026-08-10)

Uploaded `Infos_Sommerseminar_2026.pdf` (1.1MB, 7811-char docling md, 22 image placeholders with qwen
VLM descriptions). `createAthenaRefiner` returned the **fallback** (mode=single, frontmatter
`{type: document, topic: unclassified}`, entities=0, keywords=0) because the LLM pass threw
`refine_document: assistant returned no structured output` (extractRefinedDocument found neither an
`emit_refined_document` tool call nor plain-text JSON).

A short fixture (`# Test Doc ... CALEO ... SAP Group Reporting`) **succeeds** (extracts CALEO/org,
John/person, SAP Group Reporting/product + 7 keywords + correct type/topic). So the failure is specific
to **complex / image-heavy** input, not a general break.

## Root-cause hypothesis

`extractRefinedDocument` requires the model to (a) call the `emit_refined_document` tool OR (b) return a
plain JSON blob. On long markdown with many inline `![Image](images/...)` + long VLM descriptions, the
deepseek-v4-flash model does neither — likely because:
- the tool-call/JSON response is truncated or malformed under the larger prompt, or
- the model emits markdown/chat text instead of the structured emit call.
No retry exists: one failed pass → `fallbackRefinement`.

## Fix direction

- Add a **retry** (e.g. re-prompt once, or fall back to stage-1 header re-level + per-section passes which
  use smaller payloads) before giving up to `fallbackRefinement`.
- Consider **splitting image descriptions out of the refinement prompt** (images already have VLM alt text
  that need not be re-read by the refinement LLM — they can be stripped/passed via the chunks, reducing
  prompt size and noise).
- Make `extractRefinedDocument` more lenient: also accept a JSON object nested inside assistant text
  (regex extraction) before failing.
- Add a test fixture with an image-heavy docling md that asserts structured output (not fallback).

## Steps

1. codegraph explore `extractRefinedDocument` / `runRefinePass` / `refineDocument` flow.
2. Implement retry + lenient extraction (+ optional image-desc stripping).
3. Test: image-heavy fixture → structured output; simple doc regression stays green.
4. Server tests green + typecheck clean.
