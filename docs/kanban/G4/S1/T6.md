# G4.S1.T6: refine_document structured-output fails on complex docs

## Observed (2026-08-10)

Uploaded `Infos_Sommerseminar_2026.pdf` (1.1MB, 7811-char docling md, 22 image placeholders with qwen
VLM descriptions). `createAthenaRefiner` returned the **fallback** (mode=single, frontmatter
`{type: document, topic: unclassified}`, entities=0, keywords=0) because the LLM pass threw
`refine_document: assistant returned no structured output` (extractRefinedDocument found neither an
`emit_refined_document` tool call nor plain-text JSON).

A short fixture (`# Test Doc ... CALEO ... SAP Group Reporting`) **succeeds** (extracts CALEO/org,
John/person, SAP Group Reporting/product + 7 keywords + correct type/topic). So the failure is specific
to **complex / image-heavy** input, not a general break.

## Root-cause hypothesis (refined 2026-08-10 after user insight)

**The refinement LLM does NOT need the images — only the VLM text descriptions.** The md embeds
`![Image](images/...)` references (9 in this doc) purely so **llm_wiki can render images alongside text**
in the final view. For the refinement step those reference lines are noise that make the model's
constrained-sampling output unstable. The fix is to **strip image-reference lines from the refinement
prompt**, keeping the docling VLM descriptions ("The image displays a bright sky scene...") as plain text
— exactly what the refinement LLM should read. LightRAG likewise only needs the text; llm_wiki keeps the
full md (refs + image files) for display.

`extractRefinedDocument` requires the model to (a) call the `emit_refined_document` tool OR (b) return a
plain JSON blob. On long markdown with many inline image refs + VLM descriptions the model does neither.
No retry exists: one failed pass → `fallbackRefinement`.

## Fix direction (two-file design, confirmed 2026-08-10)

**Primary: strip `![Image](...)` reference lines from the refinement prompt** (keep the following VLM
description text). Refinement only reads text.

**Two-file architecture (confirmed by user)**:
- **File A** — full docling md (image refs + VLM descriptions). Consumed by **llm_wiki** for display
  (text + images).
- **File B** — md with image-ref lines stripped (text + VLM descriptions only). Consumed by **Athena
  refinement** and **RAG**.
- After refinement, **sync the corrections back to File A** (apply the refined header re-level to File A,
  keeping its image refs) → File A′ (refined headers + images) → llm_wiki.
- **RAG keeps using File B** (refined, no image refs).
- **Delete File B** once RAG ingestion is done (it's a working copy; File A′ is the durable artifact).

Additional robustness:
- Add a **retry** (re-prompt once) before giving up to `fallbackRefinement`.
- Make `extractRefinedDocument` more lenient: accept a JSON object nested inside assistant text before failing.
- Add a test fixture with an image-heavy docling md that asserts structured output (not fallback).
