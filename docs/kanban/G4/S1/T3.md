# G4.S1.T3: big-output handling + two-stage refinement for large docs

## Task

Handle large md output (per G4.S1 Spec: pi-docparser pattern + two-stage refinement).

## Big-output pattern (pi-docparser)

`refine_document` returns the **small metadata** (frontmatter, entities, keywords, quality, md ref) into
context; the **full re-leveled markdown + chunks** land on disk/storage for downstream to read by
reference — keeps large md OUT of subsequent LLM context.

## Two-stage refinement for large docs (decided 2026-08-09)

Measured reference: 827pg SAP doc = 2.17MB md, ALL h2 (3,364 headers, no h1). Header re-leveling does NOT
need the full doc:

1. **Stage 1 — header re-level (local)**: judge each header's level using header text + a few following
   paragraphs (tens of KB/batch, batched ~30-50 headers). Produces the corrected h1/h2/h3 hierarchy.
2. **Stage 2 — split by refined h1 boundary** into semantically-complete sections (<1MB each), then per
   section: chunk + entity + keyword + type/topic.

Sub-1MB docs: single full-doc pass (skip the split).

## Deliverables

- Big-output storage (full md + chunks to file/storage; metadata + refs returned).
- Two-stage refinement: local header pass → h1-boundary split → per-section full pass.
- Size-based routing (sub-1MB single-read; >1MB two-stage).
