## Context

G4.S4.T1 adds the plugin that writes the Progress Log. This ticket consumes it on the read side: the
kanban board should show each worker's latest progress at a glance (who's progressing / stuck / done)
— WITHOUT polling the opencode session API. Stalled is derived from the Progress Log timestamp.

## Task

- **Server parser**: extend the kanban parser (`server/src/kanban/...`) to parse the `## Progress
  Log` table at the bottom of each ticket file and expose the last row (timestamp/status/progress)
  per ticket in the kanban index / `/api/kanban` response.
- **KanbanTab**: show the last Progress Log row + "updated Xs ago" (row timestamp vs now) for
  in_progress tickets.
- **Stalled flag**: when status is in_progress and the last Progress Log timestamp is old (> ~3 min),
  flag the ticket as stalled in the UI. This is an observation flag only — do NOT modify frontmatter.

## Acceptance

- Parser returns the last Progress Log row per ticket.
- KanbanTab renders the row + updated-ago + stalled flag.
- Tests green (server + web).

## Notes

- Stalled is derived from the real wall-clock timestamp written by the plugin (T1) — do not rely on
  fabricated LLM timestamps.
- See §10/§12 of `docs/git-kanban-design.md`.
