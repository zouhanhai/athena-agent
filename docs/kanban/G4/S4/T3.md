## Context

G4.S4.T1 built the plugin; G4.S4.T2 built the Kanban read side. This ticket makes it real: install the
plugin on the 6900XT opencode serve and verify the full flow works end-to-end against the live
worker dispatch.

## Task

- **Deploy**: install the T1 plugin into the GLOBAL opencode plugin dir
  (`~/.config/opencode/plugins/`) so it loads for any project regardless of serve cwd; confirm it loads
  on serve startup (no plugin-load errors).
- **Fix concurrent double-claim**: the plugin currently claims up to 2x when several tool calls fire in
  the same tick (duplicate Progress Log claim rows + duplicate claim commits). Make the claim exactly
  once per session (e.g. a sync in-flight flag / promise-dedupe so only the first call claims; the rest
  wait or skip). Add a plugin unit test that fires N concurrent tool.execute.before calls and asserts
  exactly ONE claim row + ONE claim commit.
- **Fix concurrent Progress Log appends**: `tool.execute.after` also fires duplicate rows for the same
  call (e.g. `ran bash` twice with the same timestamp). Dedupe/rate-limit so a single tool call appends
  at most ONE Progress Log row. Add a unit test firing N concurrent tool.execute.after calls and
  asserting exactly ONE row per tool call.
- **Implement done double-commit (D29)**: the plugin must also regenerate + commit the kanban index
  when a worker marks a ticket done. Mechanism: subscribe to the `session.idle` event via the `event`
  hook (opencode emits `{type:"session.idle", properties:{sessionID}}` when a worker session becomes
  idle). On `session.idle`, check the ticket claimed by that session; if its frontmatter `status` is
  `done`, regenerate the kanban index and commit it as a SEPARATE commit (the worker's done commit +
  the plugin's index commit = two commits). This is a fallback so the board stays current even if the
  worker forgets to regen the index. Add a unit test: a ticket changed to done + session.idle → the
  plugin produces a separate index commit.
- **Update AGENTS.md**: remove the manual claim step from the worker workflow (status/assignee/
  session_id + commit) — the plugin auto-claims; the worker starts at "find context". Keep a note that
  the claim is automated.
- **E2E auto-claim**: dispatch a ticket to an opencode worker → confirm the plugin auto-claims exactly
  once on the first tool call (frontmatter status=in_progress + assignee + session_id in the repo,
  kanban index regenerated, ONE commit for claim).
- **E2E Progress Log**: confirm the worker's real tool activity appends Progress Log rows with real
  wall-clock timestamps.
- **E2E stalled**: verify KanbanTab shows the last row + updated-ago + a stalled flag for an
  in_progress ticket whose last Progress Log timestamp is old.

## Acceptance

- Plugin loads from the GLOBAL dir on the 6900XT opencode serve.
- Auto-claim happens exactly once (no duplicate claims), and Progress Log appends at most one row per
  tool call (no duplicate `ran ...` rows). Both verified by concurrent unit tests + end-to-end.
- When a worker marks a ticket `done`, the plugin regenerates + commits the kanban index as a SEPARATE
  commit (done double-commit, D29) — verified by unit test + end-to-end.
- AGENTS.md no longer instructs the worker to manually claim.
- Verified on the 6900XT (authoritative).
